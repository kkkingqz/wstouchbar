# Реализованные функции wstouchbar

Дата: 6 ноября 2026 года. Срез исходников: `a111213`, ветка
`stage-4-touchbard`. Отчёт сопоставляет планы с кодом и протоколами приёмки.
Статус «реализовано» означает наличие работающего кода; аппаратная проверка
указана отдельно. Проект ещё не достиг полного паритета с исходным Touch Bar.

| Панели | Открытие нажатием и удержанием, transient/persistent, геометрия относительно слота/якоря/поверхности | Проверены автоматическими тестами и пользователем в симуляторе; панели независимы у разных поверхностей |
| Несколько поверхностей | Отдельные сцены, экземпляры, захваты и панели; разделяемые системные источники | Проверены два окна симулятора разного размера. Это не готовая самостоятельная поверхность `window` для сенсорного монитора |
| Профили | Выбор по условиям, фактам и приоритету; include, кандидаты слота, явный выбор, Pending при переключении | Механизм реализован. Поставляется только `profile-default`; профилей браузера/плеера и настоящего факта активного приложения пока нет |
| Native/display | Переключение USB, получение и освобождение DRM, возврат native при потере права на устройство | Настоящие переходы и очистка проверены короткими аппаратными стендами |
| Recovery | Удержание физической Fn 8 с, переключение через CLI, маркер в `/run`, явный выход | Автоматы и сквозные сценарии пройдены; два удержания настоящей Fn ещё нужно проверить вручную |
| Мост Fn в native | Переключение нативных рядов через `hid_appletb_kbd`, возврат состояния при отпускании | Код и автоматические проверки готовы; полный ручной чек-лист ещё не пройден |
| Затемнение самой Touch Bar | Active → Dimmed → Off, учёт активности и крышки, предел подсветки от сессии, подавление пробуждающего касания | Драйвер и автоматы реализованы; передача autodim проверена на устройстве. Длительный idle, крышка и пробуждение касанием ещё требуют ручной проверки |
| Блокировка и сон | Получение logind-событий, переход native, delay-inhibitor с конечным бюджетом, восстановление подключения | Проверены на частной D-Bus и в сквозных тестах. Пять настоящих suspend/resume, гибернация и ручной lock/unlock ещё не выполнены |

Поставляемые наборы находятся в отдельных файлах:

- `controls/volume` — `plugins/controls/sets/volume.toml`;
- `controls/brightness` — `plugins/controls/sets/brightness.toml`;
- `controls/microphone` — `plugins/controls/sets/microphone.toml`;
- `system/fkeys` — `plugins/system/sets/fkeys.toml`.

Манифесты явно перечисляют файлы наборов. В default сейчас три позиции:
VOL, LIGHT, MIC; при Fn включается слой F-клавиш. Это общий набор, а не комплект
готовых раскладок для отдельных приложений.

## Разделение движка, логики и описаний

Запрошенное разделение реализовано:

1. **Движок и системная оболочка.** Ядро управляет жизненным циклом, вводом,
   сценами и очередями; исполнители выполняют обращения к ОС. Root-демон
   занимается аппаратурой и правами владельца.
2. **Логика набора.** Wasm-компонент получает типизированные события и возвращает
   изменения состояния и запросы к функциям движка. Прямого доступа к ОС через
   WASI у него нет.
3. **Описание и расположение кнопок.** TOML задаёт дерево UI, привязки к состоянию,
   действия, responsive-варианты и локальные раскладки панелей.

Общий код повторно используется без зависимости от порядка подключения:
три набора controls используют один `logic.wasm`, выбирая поведение через
`logic_config`. У каждого экземпляра своё состояние. Декларативные наборы,
например F-клавиши, могут работать вообще без Wasm.

В runtime реализованы явный выбор ревизии, подготовка и кеширование модулей,
отдельные Store, ограничения времени, памяти, таблиц и размера данных, изоляция
trap/timeout/OOM/переполнения стека и сохранение состояния с миграцией.
Неудачное обновление каталога сохраняет прежние документы и ревизии логики.

## Механизмы движка и сессии

| Область | Реализовано |
|---|---|
| Жизненный цикл | Loading/Visible/Hidden/Faulted, создание и уничтожение экземпляров, восстановление после ошибок |
| Ввод | Несколько касаний, захваты, cancel, нажатие/удержание, перетаскивание ползунка, scrubber с устойчивыми ключами записей, маршруты клавиш и отпускание при уходе владельца |
| Слои и панели | Слои по привязкам, верхний интерактивный слой, не больше одной панели на поверхность, локальная логика панели владельца |
| Действия | Очереди, lifetime, timeout, явная отмена, coalesce только ожидающего запроса; committed переживает скрытие и уничтожение интерфейса |
| Подписки | Объединение одинаковых источников, восстановление с backoff, обработка потери источника и запоздалых данных |
| Состояние и replay | Сохранение состояния, версионированные checkpoint с CoreConfig, монотонный Timestamp, запись входов и детерминированное воспроизведение |
| Описания | Строгие TOML для плагинов, наборов, профилей и привязок, проверки ссылок/схем/циклов и диагностические пути ошибок |
| Каталог | Поиск и затенение плагинов, зависимости, отключение, ревизии по содержимому, атомарный reload, inotify с объединением событий |
| UI | Текст, встроенные символы, PNG/SVG, кнопки, ползунки, индикаторы, scrubber, repeat, responsive, canvas, WGSL-эффекты, темы light/dark |
| Раскладка | Группы, слоты, фиксированные и гибкие промежутки, приоритеты сжатия/скрытия, единицы u/%w/%h, плотность поверхности |
| Рендер | CPU display list и EGL/GLES, выбор GPU, direct dma-buf import и резервный copy-путь, поворот, частичный damage, пропуск неизменённого изображения |
| Исполнители | Audio, timer, desktop через выбранный backend, spawn.run/spawn.lines, D-Bus call/property/signal |
| Процессы spawn | Квоты, отмена, таймаут, очистка потомков включая setsid, ограниченное дочитывание после смерти helper, ожидание событий без опроса каждые 5 мс |
| Устойчивость | Локальная обработка GL/accept/очередей, ограниченные журналы, отсутствие полного Core::snapshot на каждую запись журнала |
| Симулятор | Несколько Wayland-окон, масштаб, мышь и wl_touch, второе касание, правый Alt как Fn, переключение темы, изолированные socket/state |
| Инструменты | `touchbarctl render`, `status --json`, `dump`, `reload`, `sim fact/theme`, `native`, `display`, `reload --daemon` |

Ограничения: интерактивным поддеревьям разрешена анимация прозрачности, но не
сдвиг/масштабирование (D104). Декоративные элементы сохраняют преобразования.
Изменение лимита времени логики требует перезапуска. Desktop backend пока
выбирается при старте; готовыми backend являются fake и null. Команды media/open
до этапа 5 возвращают unsupported.

## Что сделано для настоящего оборудования

H1–H17 включают:

- протокол v2 с разделением направлений сообщений, проверкой peer UID,
  передачей 2–3 дескрипторов swapchain и подтверждением FramePresented;
- USB discovery/hotplug, единственный аппаратный владелец, ограниченные
  очереди и поколения операций, возврат устройства после ошибки;
- DRM probe, XRGB8888, полный/частичный commit и учёт занятых буферов;
- evdev-дигитайзер, tracking ID 0, обработку потери событий и отключения;
- физические клавиши, закрытый список ввода через uinput, динамический WatchKey;
- logind: UID активной графической сессии seat0, отзыв владельца, LockedHint,
  сон, переподключение к шине и управление inhibitor FD;
- аппаратную поверхность сессии: handshake, переподключение, новая swapchain,
  Direct/Copy, один неподтверждённый кадр и завершение неизменённого Render локально;
- системный и пользовательский юниты, KillMode=control-group, udev-изоляцию
  appletbdrm от GNOME, tmpfiles, staging install и uninstall по манифесту.

На машине проверен защищённый root unit: только CAP_SYS_MODULE, sysfs read-only
с исключениями D129, доступ к uinput и управление autodim. Короткие стенды
завершились возвратом native и восстановлением прежней Fn-службы.

Пользователь подтвердил исправление отражения букв/значков и открытие VOL.
Физическая светящаяся область 233×6 мм внесена для MacBookPro16,1; размер всего
стекла 242×11 мм не используется для плотности. Неравные промежутки кнопок
исправлены: программные эталоны дают 8/8 px. Новая физическая проверка именно
отступов ещё не выполнялась.

использовался свежий клон внутри существующего `touchbar-build`, а не новая ОС.
CI для обычных проверок, PNG, длинных свойств и fuzz уже описан в workflow;
наличие workflow само по себе не подтверждает успешный запуск GitHub Actions.

## Что ещё требуется по плану

**Завершить H18.** Не пройдены полный ручной чек-лист загрузки/входа,
пять suspend/resume и гибернация, физическая Fn/recovery, lock/unlock, крышка,
реальный restart user-systemd относительно grace 2 с, замеры idle/батареи и
задержки касание → кадр. Второго графического пользователя нет: настоящая
быстрая смена UID не проверена. Подготовленный длительный стенд не запускался;
пользователь отложил его до отдельного запроса. После приёмки остаётся итоговое
независимое ревью всей ветки этапа 4.

В журнале аппаратных переходов сохраняются предупреждения amdgpu err28.
Повторных падений GNOME на защищённых коротких стендах не было, но причина
предупреждений не установлена и полностью чистый графический стек не заявляется.

**Этап 5.** Настоящий GNOME backend и расширение, события активного окна,
команды рабочего стола и яркость экрана; media/MPRIS с transport, timeline,
перемоткой и выбором плеера; browser/navigation; open/apps; готовые профили
браузера, медиаплеера и их сочетаний. Контракты и механизмы подключения для этих
функций уже есть, готовой интеграции с приложениями пока нет.

**Этап 6.** Генерация и проверка пакета .deb, выпуск и Releases, полная
доставка через CI, установка на чистую и рабочую системы, переход wsconfig
на пакет с удалением прежнего ws-touchbar-fn. Staging install не выполняет
этот переход и не включает службы на хосте.

**После v1.** Самостоятельная поверхность window для сенсорного монитора,
батарея/профиль питания, now-playing, офисные кнопки, command-deck/capture,
другие desktop backend, расширение каталога действий и другие пункты roadmap.
