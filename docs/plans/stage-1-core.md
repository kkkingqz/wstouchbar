# План: этап 1 — ядро

Этап 0 (документ архитектуры) закрыт коммитом `408e4f1`. Открытые вопросы из [decisions.md](../architecture/decisions.md) этап 1 не блокируют.

## Цель

Написать `touchbar-core`, `touchbar-bindings` и `touchbar-testkit`. Ядро должно реализовать все автоматы из [03-core.md](../architecture/03-core.md) и проходить проверку инвариантов I1–I12 на 10⁵ случайных последовательностей. На этом этапе нет ввода-вывода, wasm, TOML, рендера и железа: всё, что ядро получает извне, приходит готовыми Rust-значениями, а логика плагинов подменяется скриптами в тестах.

## Уточнения архитектуры

Найдены при планировании и уже внесены в документы архитектуры:

1. **Карта попаданий приходит от рендера.** Вход `Layout{surface, generation, hit_map, representations}` отвечает на `Render`. Касание в экземпляр, которого нет в новой сцене, отменяется с причиной `Layout` ([03-core.md](../architecture/03-core.md)).
2. **Крейт `touchbar-model`** с общими доменными типами. От него зависят ядро, `touchbar-bindings`, а позже парсеры, runtime логики и рендер.
3. **`SystemKey` и `WatchKey`** определены в `touchbar-model`. Протокол v2 кодирует эти же типы.
4. **Поверхности** ([16-surfaces.md](../architecture/16-surfaces.md)). Ядро адресует всё через `SurfaceId`. У каждой поверхности своя сцена и свой выбор профиля, а её свойства — это факты `surface.*`. В v1 реально подключается только Touch Bar, но ядро с самого начала поддерживает несколько поверхностей одновременно: свои экземпляры на каждой, слои по поверхности-источнику клавиши (D34–D36).
5. **Единицы.** Длины в каталоге — базовая единица `u` (по умолчанию 1 % короткой стороны поверхности), `%w` и `%h`. Цепочка `[units]`: набор → профиль → поверхность. Ядро в пикселях работает только с картой попаданий, пороги жестов задаются в миллиметрах и переводятся через `px_per_mm`.

### T1. Каркас

- Workspace, `rust-toolchain.toml`, `rustfmt.toml`, `clippy.toml`, `[workspace.lints]` (`unsafe_code = "forbid"` для этих крейтов, `clippy::pedantic` выборочно).
- CI: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`. Кеш через `Swatinem/rust-cache`.
- Отдельное задание `proptest-long` вручную и по ночам: `PROPTEST_CASES=100000`.

### T2. touchbar-model

- **Идентификаторы:** `PluginId`, `SetRef` (`plugin/set`), `ProfileRef`, `SlotId`, `SurfaceId`, `InstanceId` (номер + поколение), `ContactId(NonZeroU32)`, `RequestId`, `SubscriptionId`, `TimerId`, `Generation`.
- **Поверхности:** `SurfaceKind` (`Touchbar`, `Window`, `Headless`), `SurfaceName` (`touchbar`, `window:<name>`), `SurfaceInfo` (имя, размер в пикселях, `px_per_mm`, `SurfaceCaps`), факты `surface.*` из описания. Привязки слоёв получают поле `surfaces` (`source` по умолчанию, список имён или `all`).
- **Единицы:** `Length` (`Unit(f32)` | `Percent { value, axis: Width | Height }`), разбор и сериализация `N`, `"Nu"`, `"N%w"`, `"N%h"`. `UnitSize` из `[units]` (только `%w` и `%h`), разрешение цепочки набор → профиль → поверхность, `Length::to_px(&SurfaceInfo, unit)`. `Millimeters` для порогов, `Mm::to_px(px_per_mm)`.
- **Геометрия:** `Point`, `Rect` в пикселях поверхности, `HitMap` (прямоугольники виджетов по экземплярам и слоям).
- **Факты и условия:** `FactName`, `FactValue` (bool, number, text, list of text, records), `Facts` (`BTreeMap`), `Condition` (`eq`, `in`, `exists`, `not`, `all`, `any`, глубина ≤ 8) и её вычисление.
- **Каталог:** `Catalog { plugins, sets, profiles, bindings }`.
  - `SetSpec` — в объёме ядра: дерево виджетов с id, видами (`button`, `slider`, `scrubber`, `key`, прочие как неинтерактивные), `hold_ms`, обработчиками (`on_*` → имя действия), панелями (`expanded_panel`, `press_and_hold_panel`, `dismiss_on_selection`), привязкой логики (`logic_config`), полями `persist`.
  - `ProfileSpec` — `for`, `when`, `priority`, `default`, `locked`, слоты с кандидатами.
  - Валидация (ссылки, уникальность, конфликты профилей из [08-profiles.md](../architecture/08-profiles.md)) — функция `Catalog::validate` здесь же, чтобы и парсеры, и тесты строили каталог одинаково.
- **Логика:** `LogicEvent`, `LogicUpdate { state, requests, cancel, subscriptions, presentation }`, `StatePatch`, `Origin`, `CancelReason`. Типы один к одному отражают черновик WIT из [05-logic.md](../architecture/05-logic.md).
- **Действия и подписки:** перечисления видов каталога v1 ([06-effects.md](../architecture/06-effects.md)) с параметрами, `Lifetime`, `EffectDefaults` (lifetime и timeout по виду), `EffectResult`, `EffectError`.
- **Клавиши:** `SystemKey`, `WatchKey`, `KeyPhase`.
- Все типы `Serialize`/`Deserialize`: на этом построен бортовой журнал.

Тесты: вычисление условий, валидация каталога (каждое правило — отдельный тест), разбор единиц (`200`, `"18u"`, `"6%w"`, `"0.5%h"`, ошибки на `"6px"`, `"101%w"`, `u` в `[units]` через `u`), цепочка `[units]`, сериализация туда и обратно.

### T3. touchbar-bindings

- **Модель:** `Trigger` (`key`, `keys`, `sequence`; жесты `press`, `release`, `while-held`, `hold`, `tap`, `multi-tap`), `Binding<A> { id, trigger, when, action: A }` — действие обобщённое: слои в сессии, режимы в `touchbard`.
- **Автомат:** `BindingEngine<A>::handle(now, KeyInput) -> Vec<BindingEvent<A>>` (`Fired`, `Began`, `Ended` для `while-held`), `next_deadline()` для таймеров `hold`, `tap` и `within-ms`, `reset()`.
- **Проверка набора:** одинаковые триггеры с разными действиями без разных `when` — ошибка.
- **Перенос:** `touchbard/src/recovery.rs` (удержание Fn: одно удержание переключает один раз, прерванное не срабатывает) — первый тестовый сценарий.

Тесты: таблица по каждому жесту (граничные времена ±1 мс), аккорды (порядок нажатия, отпускание одной клавиши), `sequence` с таймаутом, независимость нескольких привязок на одной клавише, `reset`. Property: после отпускания всех клавиш и истечения всех дедлайнов нет активных `while-held`. Каждое `Began` получает ровно одно `Ended`.

### T4. Ядро: каркас

- **API:** `Core::new(CoreConfig)`, `handle(now, Input) -> Vec<Output>`, `snapshot()`.
- **`Input` и `Output`** — как в [03-core.md](../architecture/03-core.md). Всё, что относится к поверхности (касания, карта попаданий, режим, кадры, клавиши, подсветка), несёт `SurfaceId`.
- **Поверхности:** `SurfaceAdded`, `SurfaceChanged`, `SurfaceRemoved`. Удаление поверхности отменяет её касания с причиной `SurfaceRemoved`, скрывает и уничтожает её экземпляры.
- **Таймеры:** реестр дедлайнов внутри ядра. При изменении ближайшего дедлайна выдаются `SetTimer` и `ClearTimer`, вход `Timer{id}` раздаётся подсистемам.
- **Факты:** хранилище и уведомление подсистем об изменениях (профиль, `when` привязок).
- **Режим** — у каждой поверхности свой: `Mode{surface, display|native}`, `Revoked{surface}`. Для поверхности в `native` ядро не выдаёт `Render` и `SendKey` (I11), касания отменяются с причиной `Mode`. Команды, которых нет в `caps` поверхности, не выдаются. `SendKey` без `inject_keys` направляется в бэкенд рабочего стола.
- **Конфигурация:** `CoreConfig` — все числовые параметры из документов: `pending-deadline` 1500 мс, backoff 1…60 с, слоты действий 8, предел `value-changed` раз в кадр, задержка сохранения 1 с.

### T5. Ядро: выбор профиля и сцена

- **Выбор профиля для каждой поверхности:** чистая функция `resolve(catalog, facts, surface_facts) -> Resolution` (шаги 0–3, `when`, `priority`) с подробным объяснением для `explain`. Перенос идей `touchbar-model/profiles.rs` (`ProfileCatalog`, `CompositionController`) без контрибуций.
- **Автомат профиля:** `Active → Pending(deadline) → Active`, правила из [03-core.md](../architecture/03-core.md).
- **Сцена на поверхность:** профиль, стек слоёв, панель и размещение экземпляров по слотам. Первый доступный кандидат слота. Отсутствующий или выключенный плагин даёт пустой слот.
- **Разница сцен:** экземпляры с тем же ключом (`slot`, `set`, `logic_config`) сохраняются, остальные уничтожаются и создаются. Выдаётся `Render(Scene{generation})`.
- **Перезагрузка каталога** (`Input::Catalog`) проходит через тот же механизм.

### T6. Ядро: экземпляры

- **Автомат:** `Loading → Hidden ⇄ Visible`, `Faulted` (backoff), `Disposed`.
- **`CreateInstance` и `DisposeInstance`**, `LogicDescribed`. Сверка описания логики с набором: неизвестное действие или поле — ошибка экземпляра (`Faulted` без повторов до перезагрузки каталога).
- **Очередь вызовов:** события одного экземпляра строго последовательны. Следующий `CallLogic` выдаётся только после `LogicUpdate` или `LogicFault` на предыдущий. Ядро копит очередь событий и схлопывает `value-changed`.
- **Применение `LogicUpdate`:** состояние; запросы, отмены и подписки (T10); панель (T8). Недопустимые части отбрасываются с `Log{warn}`.
- **Видимость** определяется сценой: экземпляр в профиле, слое или открытой панели. Под слоем экземпляр остаётся `Visible`.

### T7. Ядро: касания и виджеты

- **Таблица захватов** `(SurfaceId, ContactId) → Capture`: `Down` → проверка попадания по `hit_map` своей поверхности (панель → слои → профиль), запасной вариант — ближайший виджет в колонке не дальше 3 мм по вертикали, иначе касание никуда не идёт.
- **`Up` и `Cancel`** доставляются по таблице захватов (I1, I2).
- **Отмены** от `Hidden`, `Layer`, `Presentation`, `Profile`, `Mode`, `Revoked`, `Fault`, `Hardware`, `Layout`.
- **Автоматы виджетов:** перенос `touchbar-ui/src/gesture.rs`.
  - `GestureArena` и распознаватели: tap до 350 мс и 1.3 мм, long-press, pan от 1.0 мм, swipe от 4.0 мм и 40 мм/с. Все пороги в миллиметрах через `px_per_mm` поверхности ([16-surfaces.md](../architecture/16-surfaces.md)).
  - Поверх них — виджеты `button`, `slider`, `scrubber`, `key` с событиями из [03-core.md](../architecture/03-core.md).
  - Значение ползунка из координаты и прямоугольника виджета.
- **`origin`** у каждого события логики.

### T8. Ядро: панели

Перенос `touchbar-ui/src/presentation.rs`:
- политики размещения `anchored`, `region`, `full`;
- `transient` (с касанием-якорем) и `persistent`;
- `DismissalPolicy` (release, selection, outside-press, timeout);
- закрытие при скрытии источника.

Одновременно не больше одной панели (I4). `presentation.open` принимается только в ответ на `physical` (A5). Касания, начатые до открытия, остаются у своих целей (Б2). После закрытия логика получает `presentation-closed`.

### T9. Ядро: слои и привязки

- **`BindingEngine<LayerAction>`** внутри ядра, вход — `Key`. При смене каталога ядро выдаёт `WatchKeys` с объединением клавиш всех привязок.
- **Стек слоёв:** `layer` (пока `while-held` активен или до следующего срабатывания), `toggle-layer`, `clear-layers`. При появлении слоя касания профиля отменяются (`Layer`), открытая панель закрывается.
- **Сброс** автоматов и снятие слоёв `while-held` при `Mode` и `Revoked`.

### T10. Ядро: действия, подписки, клавиши

- **Действия:**
  - `Requested → Running → Done | Failed | Cancelled`;
  - слоты на экземпляр;
  - `coalesce` (замена ожидающего запроса);
  - `lifetime` (`until-hidden` отменяется при скрытии, `committed` доводится до конца даже после `Disposed`, I6);
  - `timeout` через таймеры;
  - поколение экземпляра в `RequestId`, поздние результаты отбрасываются (I7).
- **Подписки:** разница желаемого множества с текущим, `background`, остановка при `Hidden` и запуск при `Visible` (I5, A4), перезапуск после `SubscriptionLost` с backoff.
- **Клавиши:** учёт нажатых через `key`-виджеты и действия `key.down`. На каждое `pressed` гарантируется `released` при отмене, скрытии, сбое, уничтожении, `Mode` и `Revoked` (I9).

### T11. Ядро: сохраняемое состояние и снимок

- Поля `persist` после обновлений собираются в `Output::Persist` с задержкой 1 с, только изменившиеся.
- `CoreSnapshot`: режим, профиль и `Resolution`, слои, панель, экземпляры (состояние, очередь, запросы, подписки), захваты. Сериализуемый, для `status` и тестов.

### T12. testkit: обвязка и DSL

- **`Harness`:** виртуальные часы, автоматическая доставка `Timer` по `SetTimer`, журнал входов и выходов.
- **`FakeLogic`:** логика на Rust-замыканиях, отвечает `LogicUpdate` на `CallLogic`, по сценарию может «упасть» (`LogicFault`) или «зависнуть» (не отвечать до таймаута).
- **`FakeEffects`:** завершает запросы через заданное время с заданным результатом и подписки с данными.
- **`FakeRenderer`:** отвечает `Layout` на `Render`. Раскладка простая и детерминированная: виджеты слева направо по заданным ширинам. Настоящая раскладка не нужна.
- **Построитель каталога в коде:** `catalog().plugin("controls").set("volume", |s| s.slider("level")…).profile(…)`.
- **DSL сценариев:**
  ```rust
  scenario()
      .catalog(fixtures::controls_with_panel())
      .fact("app.id", "org.mozilla.firefox")
      .tap("volume")                                   // по id виджета
      .touch_down(1, at("microphone"))
      .after_ms(50).touch_up(1)
      .expect_effect(matches!(Effect::AudioSetMute { .. }))
      .run();
  ```
- **Запись и чтение сценариев в JSON** — формат бортового журнала.

### T13. testkit: инварианты и proptest

- **`InvariantChecker`** наблюдает поток входов и выходов (чёрный ящик) и снимки после каждого шага. Проверяет I1–I12 и сообщает первое нарушение с номером шага.
- **Стратегии proptest:**
  - каталоги из небольшого набора фикстур: 1–3 профиля, наборы с кнопками, ползунками, `key`, панели, слой F-клавиш;
  - 1–2 поверхности разных видов, размеров (2008×60, 2170×60, окно) и плотности, с добавлением и удалением поверхностей по ходу последовательности;
  - последовательности касаний с корректными фазами для 1–3 одновременных контактов;
  - вперемешку — факты, клавиши (Fn), ответы, сбои и зависания логики, результаты действий, `Mode`, `Revoked`, смена каталога, продвижение времени.
- Минимизация (shrinking) работает на уровне последовательности. Найденные контрпримеры сохраняются в `tests/regressions/` как сценарии JSON и проигрываются обычным тестом.
- По умолчанию 2000 случаев на свойство в CI, 10⁵ в задании `proptest-long`.

### T14. Сценарии регрессий

Каждый баг исходного проекта, относящийся к ядру, — отдельный именованный сценарий:

| `surfaces_are_independent` | — | две поверхности: касания, панель и слой на одной не трогают другую. Профиль выбирается по `surface.kind` |
| `same_set_on_two_surfaces` | — | один набор на двух поверхностях — два экземпляра. Скрытие на одной не трогает другой, сбой одного не роняет второй |
| `fn_layer_only_on_source_surface` | — | Fn с Touch Bar включает слой только на Touch Bar. С `surfaces = "all"` — на обеих |
| `thresholds_follow_density` | — | одинаковый сдвиг пальца в миллиметрах даёт одинаковый результат (tap или pan) на поверхностях с разной плотностью |
| `surface_removed_mid_touch` | — | удаление поверхности под пальцем отменяет касание (`SurfaceRemoved`), отпускает нажатые клавиши, уничтожает экземпляры |
| `key_without_inject_goes_to_desktop` | — | `key`-виджет на поверхности без `inject_keys` выдаёт команду `key` бэкенда рабочего стола |
