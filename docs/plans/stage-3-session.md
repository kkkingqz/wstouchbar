# План: этап 3 — сессия

Этап 2 закрыт слиянием `3a97571`, итоги — в [приёмке](../validation/stage-2.md). Открытые вопросы из [decisions.md](../architecture/decisions.md) этап 3 не блокируют. Вопрос 5 (состав профиля `default`) остаётся открытым до этапа 5, здесь используется временный профиль (предложение 5).

## Цель

Собрать `touchbar-session` без `touchbard`: загрузчик плагинов, настоящие исполнители действий, `touchbar-audio`, дерево UI из наборов, рендер, поверхности `headless` и симулятор, `touchbarctl status` и `render`.

Этап готов, когда:
- **симулятор:** `controls` работает в окне симулятора на машине разработчика. Ползунок меняет громкость PipeWire, внешние изменения громкости двигают ползунок, микрофон переключается, панель громкости открывается касанием и удержанием, Fn (правый Alt) показывает F-клавиши;
- **эталоны:** PNG наборов `controls` и `system` совпадают с эталонами на трёх размерах поверхности и в двух темах (отдельный прогон на Mesa llvmpipe, D79);
- **обычный `cargo test`:** сверяет списки примитивов и карты попаданий тех же случаев и проходит сквозные тесты сессии с поверхностью `headless`.

На этом этапе нет протокола v2 и `touchbard`: поверхность вида `touchbar` существует только в симуляторе. Нет бэкенда GNOME, модулей `media`, `open`, `apps` и категорий, пакетов. Ядро и runtime не меняются, кроме небольших дополнений API (предложения 7 и 11).

## Решения при планировании

Приняты пользователем из предложенных вариантов и внесены в документы архитектуры (D79–D81).

1. **Проверка картинки (D79).** Рендер один — GL, как в исходном проекте. Обычный `cargo test` точно сверяет детерминированный список примитивов и карту попаданий. PNG-эталоны рисует тот же GL-рендер на Mesa llvmpipe в тестах с `#[ignore]`. Их запускает `cargo xtask test-env gpu` и отдельное задание CI. Сравнение идёт с допуском, шрифт для тестов лежит в репозитории.
2. **PipeWire (D80).** `touchbar-audio` использует нативный API через `pipewire-rs`. Для сборки, в том числе для `cargo test` на свежем клоне, нужны системные `libpipewire-0.3-dev`, `clang` и `pkg-config`. Запущенный PipeWire, D-Bus, GPU и железо обычным тестам по-прежнему не нужны. Правило 1 в [13-testing.md](../architecture/13-testing.md) уточнено.
3. **Подделка рабочего стола в симуляторе (D81).** Факты меняются командами `touchbarctl sim` через управляющий сокет сессии, тема ещё и горячей клавишей окна. Боковой панели в окне симулятора нет, её можно добавить позже.

## Предложения (D82–D93)

Найдены при планировании, согласованы и внесены в журнал решений (D82–D93); остальные документы архитектуры уточняются при реализации и в приёмке S16.

1. **`touchbar-ui` без GL.** Перенесённый `touchbar-ui` строит дерево узлов, раскладывает его, растеризует глифы и SVG на CPU и выдаёт сериализуемый список примитивов. EGL, GLES, кеш текстур, шейдеры и сравнение колонок переезжают в новый крейт `touchbar-gl`. Так D79 получает чистый уровень для обычных тестов, а `unsafe` вызовов GL и EGL остаётся в одном крейте.
2. **Дерево UI строит `touchbar-scene`, а не `touchbar-sets`.** Новый чистый крейт получает `Scene` ядра, документы принятого каталога, поверхность, тему и шрифты. Он возвращает список примитивов и всё содержимое `Input::Layout`. `touchbar-sets` остаётся форматом без зависимостей рендера, а testkit может проверять сценарии на настоящей раскладке. В [README](../architecture/README.md) это меняет строку `touchbar-sets`.
3. **Загрузчик — библиотека `touchbar-loader`.** Её используют сессия, `touchbarctl render` и testkit. Вычисление ревизии содержимого (D44) существует в одном месте, `plugin_dir` из testkit переходит на него.
4. **Форматы профилей и привязок — в этапе 3.** Без них загрузчик не соберёт настоящий `Catalog`. Профили ([08-profiles.md](../architecture/08-profiles.md)) разбирает новый `touchbar-profiles`. `bindings.toml` ([09-bindings.md](../architecture/09-bindings.md)) разбирается в `touchbar-bindings`, тот же разбор позже использует `touchbard.toml`. Профили объявляются в манифесте `[[profiles]]` с `id` и `file`, как наборы, а не поиском файлов в каталоге. `categories.toml` и `touchbar-apps` остаются в этапе 5.
5. **Временный `profile-default`.** Плагин с профилем `default = true`: группа `equal-width` из `controls/volume` и `controls/brightness`, затем `controls/microphone`. Окончательный состав согласуется в этапе 5 (открытый вопрос 5).
6. **`Recorder` и `ReplayDump` переезжают из testkit в `touchbar-core`.** Бортовой журнал нужен рабочей сессии, а testkit — тестовый крейт. Формат дампа (версия 4) не меняется.
7. **Два метода ядра без изменения входов, выходов и контрольной точки.**
   - `Core::check_catalog(&Catalog)` выполняет ту же проверку, что и приём `Input::Catalog`. Загрузчик отправляет ядру только прошедший её каталог, поэтому оболочка точно знает, какие документы принятого каталога отдавать рендеру.
   - `Core::pending_persist()` только читает отложенные записи. При завершении сессии оболочка записывает их сразу, не теряя последнюю секунду изменений.
8. **Управляющий сокет сессии.** `$XDG_RUNTIME_DIR/touchbar/session-control.sock`, `SOCK_STREAM`, кадр — длина `u32` LE и JSON с полем версии, не больше 16 МиБ. Каталог создаётся с правами 0700, клиент проверяется по `SO_PEERCRED`: принимается только тот же UID. Снимок ядра не помещается в 32-байтовые сообщения `touchbard`, поэтому формат отдельный.
9. **Поверхность `headless` в двух режимах:** только список примитивов (обычные тесты, без GL) и PNG (GL). Симулятор рисует GL вне экрана и копирует кадр в буфер `wl_shm`, как `preview_output.rs` исходного проекта. Отдельная EGL-поверхность окна не нужна.
10. **Неготовые модули до этапа 5.** `media.*` и `open.uri` возвращают `unsupported`. `desktop = "gnome"` и `auto` в GNOME выбирают `null` с предупреждением.
11. **Описание логики при загрузке.** Компиляция и проверка ABI (`Compiler::prepare`) идут в рабочем потоке. После `install` главный поток получает описание через новый `Runtime::describe(plugin, revision)`, кеш которого общий с `create`, и сверяет с ним наборы плагина (`SetFile::validate_bindings`). Это один вызов `describe` на ревизию с обычным пределом времени.
12. **Сквозные тесты этапа 3 — внутри процесса.** Библиотека сессии, поверхность `headless`, поддельный рабочий стол и поддельные исполнители. Тест настоящего бинарника с поддельным `touchbard` через сокет — этап 4, вместе с протоколом.

## Уточнения после чтения плана (D94–D95)

- **Первоначальная загрузка и reload (D94).** При первом запуске повреждённый плагин пропускается целиком с диагностикой. При перезагрузке ошибка любого плагина отклоняет всё обновление: сохраняются прежний каталог и его документы, ревизии работающей логики и текущая конфигурация. Частичного принятия исправных плагинов при ошибочном reload нет.
- **Ранняя команда render (D95).** Минимальный офлайн `touchbarctl render` реализуется в S7 с загрузчиком и уже готовыми S5/S6. S13 добавляет управляющий сокет и остальные команды, а не откладывает появление render.

```
  touchbar-profiles/      формат profiles/*.toml → ProfileSpec + раскладка профиля
  touchbar-scene/         Scene + документы → дерево UI → список примитивов + Layout

  touchbar-desktop/       трейт бэкенда, факты, команды; бэкенды null и fake
  touchbar-effects/       исполнитель: диспетчеризация, timer, spawn, dbus, объединение подписок, fake
  touchbar-audio/         PipeWire: audio.watch, set-volume, set-mute
  touchbar-session/       библиотека оболочки + бинарник: цикл событий, поверхности, симулятор, сокет
  touchbarctl/            status, render, dump, reload, sim
  touchbar-bindings/      + разбор bindings.toml
  touchbar-core/          + Recorder/ReplayDump, check_catalog, pending_persist
xtask/                    build-plugins, test-env gpu|dbus|pipewire
plugins/

  profile-default/        временный профиль (предложение 5)
assets/fonts/test/        шрифт для тестов и эталонов, с лицензией
```

Новые внешние зависимости — те же версии, что в исходном проекте, если они совместимы, иначе актуальные. Версии фиксируются в `Cargo.lock` на начало работ.
- рендер: `glow`, `khronos-egl` (`dynamic`: libEGL загружается при запуске, не нужен при сборке), `cosmic-text`, `resvg`, `taffy`, `naga` (`wgsl-in`, `glsl-out`), `png`;
- окно симулятора: `wayland-client`, `wayland-protocols`;
- исполнители и модули: `pipewire`, `zbus`, `rustix` (группы процессов, сигналы, `PR_SET_PDEATHSIG`);
- оболочка: `async-io`, `futures-lite`, `async-channel`, `inotify`, `tracing`, `tracing-subscriber`, `tracing-journald`.

Системные зависимости сборки — `libpipewire-0.3-dev`, `clang` и `pkg-config` (D80). `libdrm-dev`, `libgbm-dev` и `libudev-dev` из [14-packaging.md](../architecture/14-packaging.md) понадобятся только `touchbard` на этапе 4.

`unsafe_code = "deny"` с `allow` только на модулях, которым нужен `unsafe`, и комментарием `SAFETY` у каждого блока:
- в `touchbar-gl` — вызовы GL и EGL;
- в `touchbar-effects` — `pre_exec` для `PR_SET_PDEATHSIG`.

В остальных крейтах остаётся `forbid`.

### S1. Каркас

- Новые крейты и `xtask` в workspace. Исключения `unsafe_code` по разделу «Состав».
- **CI.** Во всех заданиях перед сборкой ставятся `libpipewire-0.3-dev`, `clang` и `pkg-config`. Новое задание `render` на push и pull request ставит Mesa (`libegl1`, `libegl-mesa0`, `libgles2`, `libgl1-mesa-dri`) и запускает `cargo xtask test-env gpu`. При расхождении эталонов diff-изображения сохраняются артефактом.
- **`xtask test-env gpu|dbus|pipewire`** запускает тесты с `#[ignore]` нужного окружения по фильтру имён и проверяет, что окружение доступно. Если окружения нет, команда завершается ошибкой, а не пропускает тесты.
- **Тестовый шрифт.** Inter под OFL 1.1 в `assets/fonts/test/` вместе с текстом лицензии. Тесты и эталоны используют только его, системные шрифты в них не участвуют.

### S2. touchbar-ui без GL

Перенос `touchbar-ui` из `d2f9dfd`, около 9100 строк. Не переносятся `gesture.rs` и `presentation.rs` (их автоматы уже в ядре), GL-рендер (уходит в S6) и зависимость от `touchbar-protocol`.

- **Узлы** (`foundation.rs`): контейнеры, кнопки, ползунки, индикаторы, содержимое scrubber, canvas, shader-effect, изображения, значки, текст, промежутки, motion. `RetainedUi` с пометкой изменённых узлов, `FrameScheduler`.
- **Раскладка узлов** — flex через taffy. На вход приходят пиксели, единицы переводит S5.
- **Текст.** cosmic-text с явно переданным `FontSystem`: в сессии — системные шрифты, в тестах — шрифт из S1. Форма строки, измерение, обрезка с многоточием. Глифы растеризуются на CPU (swash) в маски, GL получает готовые маски.
- **SVG** через resvg в маски или RGBA с кешем по содержимому.
- **Символы.** Встроенные SVG-символы исходного проекта. Имена из состояния логики (`volume`, `muted`, `microphone`, `brightness` и другие) сопоставляются символам. Неизвестное имя рисуется заглушкой с одним предупреждением на имя.
- **Палитра:** роли цветов, темы light и dark, акцент.
- **Список примитивов** `DisplayList`. Самодостаточный сериализуемый пакет команд и таблицы ресурсов со стабильными ключами; данные разделяются через Arc в памяти и включаются в JSON (D96). Порядок команд детерминированный. Прямоугольники округлены до целых физических пикселей по правилам [16-surfaces.md](../architecture/16-surfaces.md), размер шрифта не округляется.
- **Шейдеры.** WGSL из `shader-effect` проверяется naga при загрузке, без GL. Список примитивов ссылается на программу по хешу исходника и несёт uniforms.

Тесты:
- перенесённые тесты UI, кроме жестов и панелей;
- детерминизм: два построения одного дерева дают одинаковый список;
- список примитивов переживает JSON туда и обратно без изменений.

### S3. touchbar-layout

Перенос `touchbar-layout`, около 1250 строк.

- **Полоса профиля:** слоты, группы (`equal-width`, `spacing`), `fixed-space` и `flexible-space` (`minimum`, `weight`), приоритеты видимости и сжатия, глубина групп до 8. Работает в пикселях, длины переводит вызывающий.
- **Слот** согласует ширину с `minimum`, `width`, `maximum` и `grow` корня набора. Вариант `responsive` выбирается по `minimum_width`, как в исходном проекте.
- **Панели** по D50: `region` — слот владельца, `full` — поверхность, `anchored` — от прямоугольника якоря и слота владельца, с `minimum_width`, `preferred_width` и `maximum_width`, в пределах поверхности.

Тесты: перенесённые и новые на 2008×60, 2170×60 и 1200×160 для `u`, `%w` и `%h`.

### S4. Форматы профилей и привязок

- **`touchbar-profiles`** разбирает `profiles/*.toml` по [08-profiles.md](../architecture/08-profiles.md):
  - поля `version`, `id`, `for` (`app`, `category`, `locked`), `when`, `default`, `priority`, `include`, `[units]`;
  - `when`: равенство, `in`, `exists`, `not`, `all`, `any`, вложенность до 8;
  - `include` — ссылка `plugin/profile`, циклы и цепочки длиннее 8 отвергаются;
  - `[[element]]`: `slot` (`items` — кандидаты по порядку), `fixed-space`, `flexible-space`, `group` с вложенным `element`.
- **Строгость** — как в `touchbar-sets`: `deny_unknown_fields`, ошибки с файлом, путём в TOML и строкой. Профиль даёт `ProfileSpec` для ядра и раскладку профиля для S5.
- **Манифест:** `[[profiles]]` с `id` и `file` (предложение 4).
- **`bindings.toml`** в `touchbar-bindings` по [09-bindings.md](../architecture/09-bindings.md):
  - триггеры `key`/`keys`, `gesture`, `ms`, `count`, `within-ms`, `sequence`;
  - действия `layer`, `toggle-layer`, `clear-layers`, `surfaces`, `when`, `id`, `disabled`;
  - разбор обобщён по типу действия, чтобы этап 4 разбирал действия `touchbard` тем же кодом.
- **Слияние привязок.** Привязки плагинов идут в порядке загрузки. Пользовательский `$XDG_CONFIG_HOME/touchbar/bindings.toml` заменяет привязку с тем же `id` или отключает её.

Тесты:
- отдельный случай на каждое правило проверки;
- разбор туда и обратно;
- профили и привязки плагинов из `plugins/`;
- примеры из 08 и 09.

### S5. touchbar-scene

Чистый построитель кадра:

```rust
let frame = scene_renderer.frame(&surface, &core_scene, &documents, theme, &mut fonts, now, motion_policy)?;
// frame.display_list — для touchbar-gl или для сравнения в тестах
// frame.layout       — hit_map, representations, scrubbers, slots, presentation для Input::Layout
```

- **Дерево из набора.** Перенос `touchbar-plugin-host/src/sets/renderer.rs`, около 840 строк:
  - все узлы схемы этапа 2 и привязки `*_from`;
  - `visible_from = false` исключает узел из раскладки (A7);
  - `repeat` по записям с `record.*`, `responsive` по ширине;
  - `key` и `key-row` с подписями `SystemKey`;
  - геометрия scrubber и смещение из `interactions` (D47);
  - значение ползунка из `interactions` во время перетаскивания, нажатие и выбор;
  - `canvas_from`, `shader-effect`, motion;
  - лимиты узлов и текста — как `HostLimits` исходного проекта.
- **Список scrubber (D99).** Обязательны `repeat_from`, `repeat_key` и визуальный `template`; scalar `value/value_from` запрещены. Жесты и `Selected` принадлежат самому scrubber.
- **Изображения** узла `image` берутся из документов каталога. Загрузчик читает их из каталога плагина (S7).
- **Единицы.** Цепочка «набор → профиль → поверхность», у слоя — «набор → поверхность». Округление по 16-surfaces.
- **Статусы:** `Loading` — заготовка без содержимого, `Faulted` — заглушка, `Hidden` не рисуется.
- **Плоскости.** Профиль, затем слои: рисуется и принимает касания только верхний слой. Панель — поверх своей области по D50.
- **Выход:**
  - карта попаданий по экземплярам и плоскостям;
  - выбранные варианты `responsive`;
  - геометрия scrubber;
  - границы всех слотов, включая пустые;
  - границы панели.
- **Повторное использование.** Поддерево экземпляра перестраивается только при изменении его состояния, взаимодействий, единиц, темы или ширины слота. Раскладка профиля пересчитывается только при смене структуры сцены или ширины слотов ([10-rendering.md](../architecture/10-rendering.md)).

Тесты, все в обычном `cargo test`:
- **эталоны списков примитивов и карт попаданий.** Случаи:
  - `volume` в узком и широком варианте и с открытой панелью;
  - микрофон с mute и недоступный;
  - `brightness`;
  - заглушка `Faulted`;
  - слой `fkeys` без Esc и с Esc.

  Каждый случай снимается на 2008×60, 2170×60 и 1200×160 (вид `window`), в тёмной и светлой теме. Эталоны обновляются через `UPDATE_GOLDEN=1`;
- **testkit.** `SceneRenderer` можно передать в `Harness` вместо `FakeRenderer`. Отдельный файл прогоняет сценарии L12 controls на настоящей геометрии.

### S6. touchbar-gl

- **EGL.** Выбор устройства по 10-rendering: `TOUCHBAR_RENDER_NODE`, затем `boot_vga`, затем первый узел; `EGL_EXT_platform_device`, surfaceless как запасной вариант. GLES 3.0.
- **Рендер списка примитивов.** Перенос `Renderer` из `touchbar-ui/src/lib.rs`: программы фигур, градиентов, линий, сеток и изображений, кеш текстур масок и изображений, WGSL → GLSL ES 300 через naga. Рисует в FBO вне экрана, читает RGBA и сохраняет PNG.
- **Ориентация.** Поворот в физическую раскладку буфера (portrait 60×N у `appletbdrm`) делается в GL. Реализуется и проверяется сейчас, используется на этапе 4.
- **Частичная перерисовка.** Перенос сравнения колонок шейдером из `touchbar-sessiond/gpu.rs`. Не больше 8 областей с объединением. Неизменившийся кадр не отправляется, первый кадр после смены режима или переподключения полный.

Тесты `#[ignore = "requires EGL (Mesa llvmpipe)"]`, запуск через `cargo xtask test-env gpu`:
- **PNG-эталоны** всех случаев S5, нарисованные из их списков примитивов. Допуск задаётся в тесте: разница канала и доля отличающихся пикселей. При расхождении diff сохраняется в `target/golden-diff/`;
- **damage:** изменение одного экземпляра даёт области только его колонок, отсутствие изменений не даёт кадра;
- **поворот:** portrait-буфер совпадает с повёрнутым эталоном.

### S7. touchbar-loader

- **Пути поиска** по [04-plugins.md](../architecture/04-plugins.md). Каталог `--plugins DIR` встаёт перед стандартными. При совпадении `id` первый найденный плагин побеждает целиком.
- **Рабочий поток** читает манифест, наборы, профили, привязки и изображения наборов (с лимитом размера) и вычисляет ревизию — хеш содержимого (D44). Компилирует логику через `Compiler::prepare`.
- **Главный поток** устанавливает модули (`install`), получает описания (`Runtime::describe`, предложение 11) и сверяет наборы. Затем собирает `Catalog`, проверяет его через `Core::check_catalog` (предложение 7) и вызывает `retain_modules` для принятого каталога.
- **`config.toml`:** `disabled`, `profile-for` (общий и по поверхностям), `[app.*]` (хранится для этапа 5), `[logic] time-limit-ms`, `desktop`, `log`. Строгий разбор. Ошибка в файле оставляет прежнюю конфигурацию с предупреждением.
- **Ошибки и конфликты.** При первоначальной загрузке плагин с ошибкой пропускается целиком, а ошибка попадает в журнал и `status`. При reload такая ошибка отклоняет обновление целиком (D94). Конфликты профилей и выбор в `profile-for` — по 04-plugins и 08-profiles.
- **Лимит и ресурсы (D100–D101).** Изменение time-limit-ms требует перезапуска и отклоняет reload целиком. Изображения объявляются через [[assets]]: id/file/kind/width/height; PNG проверяется на соответствие размеров растра.
- **Перезагрузка.** inotify на каталогах плагинов и `config.toml` с объединением событий за 200 мс, а также запрос `reload`. Ошибка чтения, разбора, подготовки или проверки любого плагина либо конфигурации сохраняет прежние каталог, документы и конфигурацию (A12, D94); ошибка видна в диагностике. Очистка модулей выполняется по прежнему принятому каталогу.
- **Результат** — принятый `Catalog` вместе с документами для S5: `SetFile`, раскладки профилей и изображения, — плюс список проблем.
- **testkit.** `plugin_dir` переходит на загрузчик, ревизия считается в одном месте.
- **Минимальный `touchbarctl render` (D95).** Офлайн-команда по интерфейсу S13: загрузчик, один слот с набором, `--state`, размер поверхности, тема и выходной PNG через S5/S6. Не требует запущенной сессии или управляющего сокета. Проверка PNG — `#[ignore]` в `test-env gpu`.

Тесты на временных каталогах:
- порядок путей и затенение одного плагина другим;
- `disabled` и `requires`;
- конфликт профилей и его разрешение через `profile-for`;
- стабильность ревизии: повторное чтение не меняет её, изменение TOML или wasm меняет;
- повреждённый плагин при первом запуске пропускается, остальные проходят проверку;
- ошибка одного плагина при reload сохраняет весь предыдущий каталог, его документы и конфигурацию; изменения исправных плагинов также не принимаются (A12, D94);
- ранний офлайн render — `#[ignore]` в `test-env gpu`, эталон из S6;
- inotify;
- повреждённый `config.toml`.

### S8. touchbar-desktop

- **Типы** из [07-desktop.md](../architecture/07-desktop.md): трейт `DesktopBackend`, `BackendEvent`, `Capabilities`, `DesktopCommand`, `DesktopError`.
- **Жизненный цикл** `Connecting → Ready → Lost` с backoff. При `Lost` оболочка снимает все факты бэкенда.
- **`null`** — нет фактов и команд, любая команда даёт `unsupported`.
- **`fake`** для симулятора и тестов:
  - любые факты задаются командами;
  - `display.brightness` хранится в памяти и меняется командой `brightness.set`;
  - `shortcut`, `key`, `workspace.activate` и `app.launch` пишутся в журнал и завершаются успешно.

Тесты: жизненный цикл и снятие фактов при `Lost`, команды `fake`.

### S9. touchbar-effects

Исполнитель выходов `StartEffect`, `CancelEffect`, `Subscribe` и `Unsubscribe`. Результаты возвращаются в цикл как `EffectDone`, `SubscriptionData` и `SubscriptionLost`.

- **Диспетчеризация** по каталогу [06-effects.md](../architecture/06-effects.md):
  - `audio.*` → S10;
  - `desktop.*` → бэкенд рабочего стола;
  - `media.*` и `open.uri` → `unsupported` до этапа 5 (предложение 10).

  Ключ `key.*` исполняет само ядро через `SendKey` и `DesktopKey`.
- **Объединение подписок (D35).** Одинаковые вид и параметры дают один источник, данные рассылаются всем `SubscriptionId`. Источник останавливается после последнего `Unsubscribe`. Обрыв источника даёт `SubscriptionLost` всем подписчикам.
- **`timer.after`, `timer.interval`** (минимум 16 мс).
- **`spawn.run` и `spawn.lines`:**
  - `argv` без shell, `env` поверх окружения сессии, `stdin`;
  - `max-output` с флагом `truncated`;
  - своя группа процессов, `PR_SET_PDEATHSIG`;
  - отмена по общим правилам: SIGTERM группе, через 1 с — SIGKILL;
  - квоты 4 процесса на экземпляр и 64 на сессию — страховка поверх квот ядра.
- **`dbus.call`, `dbus.signal`, `dbus.property`** через zbus. Значения кодируются как сигнатура D-Bus плюс JSON, варианты — `{"sig", "value"}`.
- **`fake`** для симулятора (`--effects=fake`) и тестов: задержки и результаты по видам действий, как `FakeEffects` testkit.

Тесты:
- **обычные:** spawn через небольшой тестовый бинарник крейта (вывод, обрезка, код возврата, отмена убивает группу, таймаут, квоты); таймеры; объединение подписок; property-тест кодирования D-Bus туда и обратно;
- **`#[ignore]`, `test-env dbus`:** вызов, сигнал и свойство на приватной `dbus-daemon`.

### S10. touchbar-audio

- **Поток.** Отдельный поток с главным циклом PipeWire. Команды и события ходят по каналам.
- **Устройства по умолчанию.** Цели `default-sink` и `default-source` следуют за метаданными `default.audio.sink` и `default.audio.source`. Смена устройства шлёт новое состояние.
- **`audio.watch`** даёт `AudioState {available, volume, muted, name}` при подписке и при каждом изменении.
  - Громкость в кубической шкале, как у `wpctl` и GNOME. Исходный проект брал значения из `wpctl`, поэтому логика `controls` не меняется.
  - Если у узла есть маршрут устройства, громкость и mute читаются и пишутся на маршруте, как в pipewire-pulse. Иначе — в `Props` узла.
- **`audio.set-volume`** — уровень 0.0–1.5. **`audio.set-mute`** — `on`, `off` или `toggle`, результат — новое значение.
- **Нет устройства или PipeWire** — `available = false`. Обрыв соединения даёт `SubscriptionLost` и переподключение по общему backoff.

Тесты:
- **обычные:** перевод кубической шкалы, выбор маршрута или `Props`, следование за устройством по умолчанию — на поддельном источнике событий;
- **`#[ignore]`, `test-env pipewire`:** приватный PipeWire и WirePlumber с null-устройствами во временном `XDG_RUNTIME_DIR`. Проверяются подписка, изменение громкости извне, `set-volume`, `set-mute` и смена устройства по умолчанию.

### S11. Оболочка touchbar-session

Библиотека и бинарник. Синхронное ядро цикла (`Session::handle_event`, `pump`) отделено от асинхронной обвязки источников событий. Время задаёт `Clock`: в бинарнике монотонные часы от старта, в тестах — ручные.

- **Цикл.** Один главный поток на `async-io`:
  - таймеры ядра;
  - каналы исполнителей, бэкенда, загрузчика и PipeWire;
  - поверхности;
  - управляющий сокет;
  - SIGTERM и SIGINT.

  Выходы ядра обрабатываются очередью, без рекурсии. Ответы runtime и рендера тоже становятся входами этой очереди.
- **Runtime.**
  - `FsStore` в `$XDG_STATE_HOME/touchbar`.
  - Пределы `CoreConfig` и `RuntimeConfig.limits` берутся из одного источника, `[logic] time-limit-ms` применяется к обоим.
  - Журнал гостя уходит в journald с полями экземпляра, не больше 100 строк в секунду на экземпляр.
- **Входы ядра от окружения.**
  - Бэкенд: `Ready` даёт `DesktopCapabilities`, `Fact` — `Input::Fact`, `Lost` снимает его факты.
  - Локаль из `LC_ALL`, `LC_MESSAGES` и `LANG` передаётся в `Input::Locale`.
- **Кадры.**
  - `Render` → S5 → сразу `Input::Layout` → растеризация (S6), если поверхности нужны пиксели → показ → `FrameDone`.
  - Не больше одного кадра в работе на поверхность. Анимации запрашивают кадры не чаще 60 в секунду.
- **Поверхности.** Трейт поверхности с `SurfaceInfo`, событиями касаний и клавиш, показом кадра и завершением. Реализации — `headless` (предложение 9) и симулятор (S12).
- **Журнал.**
  - `tracing` в journald, если задан `JOURNAL_STREAM`, иначе в stderr.
  - Уровень из `TOUCHBAR_LOG` или `log` в `config.toml`.
  - Повторяющиеся ошибки подавляются: первая сразу, затем сводка раз в минуту ([12-diagnostics.md](../architecture/12-diagnostics.md)).
- **Бортовой журнал.** `Recorder` из ядра (предложение 6). Дамп пишется в `$XDG_STATE_HOME/touchbar/dumps/` при `LogicFault` и `InstanceFault` (не чаще раза в минуту) и по запросу, хранятся последние 10 файлов.
- **Завершение.** Отложенные записи из `Core::pending_persist` пишутся сразу (предложение 7), экземпляры уничтожаются, процессы `spawn` получают SIGTERM.
- **Бинарник.** `touchbar-session [--plugins DIR] [--simulator --surface …] [--desktop=null|fake] [--effects=fake] [--headless WxH@ppmm]`. Пользовательский юнит и пакет — этап 6.

Тесты: `pump` с ручным временем — порядок обработки, отсутствие рекурсии, один кадр в работе, ограничение частоты анимаций, запись при завершении, ротация дампов, подавление повторов журнала.

### S12. Симулятор

`touchbar-session --simulator [--surface touchbar=2008x60@6.2ppmm] [--surface window:test=1200x160@4ppmm]` ([11-tooling.md](../architecture/11-tooling.md)).

- **Окно.** Каждая поверхность — отдельное окно `xdg_toplevel`. Кадр рисуется GL вне экрана и копируется в `wl_shm` (предложение 9). Перенос `preview_output.rs` исходного проекта с масштабом вывода.
- **Ввод.** Мышь работает как палец, с Shift — как второе касание. Правый Alt — это Fn, `F1`–`F12` и `Esc` приходят как отслеживаемые клавиши. Касания `wl_touch` тоже поддерживаются.
- **Возможности поверхности.** `touchbar` в симуляторе имеет `watch_keys` и `inject_keys`, введённые клавиши только пишутся в журнал. Режимов и подсветки у неё нет. Поверхность `window:<name>` повторяет возможности будущего `window`.
- **Подделки.** `--desktop=fake` (D81) и `--effects=fake`. Без `--effects=fake` `audio` работает по-настоящему. `desktop.shortcut` и ключи только пишутся в журнал. Горячая клавиша окна (Ctrl+T) переключает тему поддельного рабочего стола.

Ручная проверка (входит в S16):
- громкость и микрофон на настоящем PipeWire;
- панель касанием и удержанием 420 мс;
- Fn и F-клавиши;
- смена темы;
- яркость через `touchbarctl sim fact display.brightness=0.4`;
- две поверхности одновременно.

### S13. Управляющий сокет и touchbarctl

- **Изоляция симулятора (D103).** Основная сессия сохраняет путь предложения 8. Симулятор использует `$XDG_RUNTIME_DIR/touchbar/simulator/session-control.sock` и корень состояния `$XDG_STATE_HOME/simulator`; `touchbarctl --simulator` выбирает его, `sim` выбирает автоматически.
- **Сокет сессии** по предложению 8. Запросы: `Status`, `Dump`, `Reload`, `SimFact {name, value | null}`, `SimTheme`. Команды `Sim*` доступны только с `--desktop=fake`.
- **`touchbarctl status [--json]`** показывает часть сведений из 12-diagnostics, которую знает сессия, по поверхностям:
  - активный профиль и путь выбора, слои, панель;
  - экземпляры с состоянием и временем последнего вызова;
  - подписки и их перезапуски, действия в работе;
  - ошибки загрузки плагинов и конфликты;
  - время кадра и вызовов wasm, p50 и p99.

  Сведения `touchbard` добавляются на этапе 4.
- **`touchbarctl dump [-o FILE]`, `reload`, `sim fact NAME=VALUE | --unset NAME`, `sim theme light|dark`.**
- **Офлайн-команда из S7:** `touchbarctl render PLUGIN/SET [--state FILE] [--surface 2008x60@6.2ppmm] [--theme dark] [--plugins DIR] -o out.png` работает офлайн:
  - загрузчик S7 (без компиляции логики, если не нужна);
  - один экземпляр в профиле из одного слота;
  - `--state` — JSON `StatePatch`, по умолчанию пустое состояние;
  - S5 и S6 на `headless`.

Тесты:
- кадрирование и версии протокола сокета, отказ чужому UID, предел размера;
- `status`, `dump` и `reload` против сессии из S15 через настоящий сокет во временном каталоге;
- `render` — `#[ignore]` в `test-env gpu`, сравнение с эталоном S6.

### S14. Плагины и xtask build-plugins

- **`plugins/system/bindings.toml`:** `fn-layer` — Fn удерживается → слой `system/fkeys` ([09-bindings.md](../architecture/09-bindings.md)).

## Риски

| Риск | Что делаем |
|---|---|
| Эталоны PNG зависят от версии Mesa | Допуск в сравнении. Точная проверка остаётся на уровне списка примитивов. Приёмка — в закреплённом контейнере Ubuntu 26.04. Обновление — `UPDATE_GOLDEN=1` с diff в отчёте |
| Шрифты различаются между машинами | Тесты и эталоны используют только шрифт из репозитория. Системные шрифты — только в рабочей сессии |
| Громкость по маршруту устройства ведёт себя не так, как ползунок GNOME | Поведение pipewire-pulse и кубическая шкала. Ручная сверка с ползунком GNOME в S16 |
| `pipewire-rs` и `clang` усложняют сборку | Код PipeWire только в `touchbar-audio`, версии закреплены, зависимости перечислены в CI и `testing.md` (D80) |
| `unsafe` в GL, EGL и `pre_exec` | Только в отмеченных модулях с `SAFETY`. Остальные крейты — `forbid` |
| Этап больше прошлых | Промежуточная точка S5/S6: кадр набора без сессии. Исполнители S8–S10 идут параллельно рендеру |
| Повторный вход в цикл событий (ответ runtime внутри обработки выхода) | Очередь входов без рекурсии, тесты `pump` с ручным временем |
| Готовые модули и документы принятого каталога расходятся | `Core::check_catalog` до отправки. Оболочка меняет документы рендера в той же итерации, что и каталог ядра, а `retain_modules` вызывается по принятому каталогу |
