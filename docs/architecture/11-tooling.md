# Инструменты

## touchbarctl

| Команда | Что делает | С кем говорит |
|---|---|---|
| `status` | режим, владелец, recovery, профиль и причина выбора, экземпляры и их состояния, подписки и действия в работе, время кадра и вызовов wasm, ошибки плагинов | `touchbard` + сессия |
| `explain [--app ID]` | путь выбора профиля: факты, категории, кандидаты, `when`, результат. С `--app` — «что будет для этого приложения» | сессия или офлайн по каталогу |
| `check [DIR…]` | проверить плагины, профили, категории и привязки без запуска сессии | офлайн |
| `render PLUGIN/SET [--state FILE] [--surface 2008x60[@6.2ppmm]] [--theme dark] -o out.png` | отрисовать набор в PNG без железа | офлайн (headless) |
| `replay FILE` | проиграть бортовой журнал или сценарий и показать выходы ядра, можно с `--png` по кадрам | офлайн |
| `dump [-o FILE]` | сохранить бортовой журнал сессии | сессия |
| `dev DIR` | подменить плагин в работающей сессии, перезагружать его при пересборке wasm и правке TOML | сессия |
| `reload` | перечитать плагины и конфигурацию | сессия |
| `native`, `display` | включить или выключить recovery | `touchbard` |
| `sleep pre\|post` | для system-sleep (root) | `touchbard` |
| `setup` | включить расширение GNOME, проверить окружение (`doctor`), запустить сессию | пользователь |
| `doctor` | проверки: драйверы и режим, права, юниты, расширение, конфликты (`tiny-dfr`, свои правила `hid-appletb-kbd`), плагины, конфликты профилей | всё |

Вывод по умолчанию рассчитан на человека, `--json` — для скриптов и тестов.

## Симулятор

`touchbar-session --simulator [--surface touchbar=2008x60@6.2ppmm]` открывает окно Wayland (`xdg_toplevel`), которое изображает поверхность `touchbar` вместо `touchbard`. Это не будущая поверхность `window` для сенсорных мониторов ([16-surfaces.md](16-surfaces.md)): симулятор сохраняет размеры, плотность и возможности Touch Bar.
- Мышь работает как палец: обычное нажатие использует контакт 1, нажатие с Shift — контакт 2. Контакт не меняется до отпускания, даже если отпустить Shift; одновременные касания доступны через `wl_touch`.
- Правый Alt — это Fn, а клавиши `F1`–`F12` и `Esc` передаются как отслеживаемые.
- `--desktop=fake` подменяет факты рабочего стола. Они меняются командами `touchbarctl sim fact NAME=VALUE` и `touchbarctl sim theme light|dark` через управляющий сокет сессии, тема ещё и Ctrl+T в окне (D81).
- Действия `key` и `desktop.shortcut` только пишутся в журнал. Остальные модули работают по-настоящему, если не задан `--effects=fake`.

Симулятор использует тот же код, что и рабочая сессия, отличается только реализация поверхности. Настоящий Touch Bar продолжает работать параллельно. Симулятор — отдельный процесс с независимыми каталогом, фактами и исполнителями (D103). Его сокет — `$XDG_RUNTIME_DIR/touchbar/simulator/session-control.sock`, сохраняемое состояние и дампы лежат под `$XDG_STATE_HOME/simulator/touchbar/`. `touchbarctl --simulator status`, `dump` и `reload` обращаются к нему; команды `touchbarctl sim …` выбирают этот сокет автоматически. Одновременно работает не более одного симулятора пользователя; в нём можно открыть до восьми поверхностей.

Симулятор может открыть несколько поверхностей сразу, в том числе изображающих будущий вид `window`:

```bash
touchbar-session --simulator --surface touchbar=2008x60@6.2ppmm --surface window:test=1200x160@4ppmm
```

Размер каждой поверхности фиксирован аргументом запуска: это физические пиксели кадра, а размеры окна в координатах Wayland учитывают целочисленный масштаб вывода. При неделимом размере буфер дополняется крайними пикселями справа и снизу. GL рисует вне экрана; `wl_shm` передаёт кадр композитору, освобождение буферов и подтверждение кадра обрабатываются отдельно.

Так работа с несколькими поверхностями проверяется в v1, хотя настоящая поверхность `window` ещё не реализована.

Приватная проверка транспорта (Weston headless и Mesa EGL, без подключения к рабочему столу):

```sh
cargo test -p touchbar-session --test simulator_private -- --ignored --nocapture
```

## Dev-режим

`touchbarctl dev ./plugins/controls`:
1. Сессия добавляет каталог первым в путь поиска (`--dev`).
2. При изменении `*.toml` или `*.wasm` плагин перезагружается. Его экземпляры проходят `Disposed → Loading`, сохраняемое состояние остаётся.
   Ревизия содержимого (D44) пересоздаёт также экземпляры наборов других плагинов, использующих изменённый поставщик общей логики. Повторное чтение прежнего содержимого экземпляры сохраняет.
3. Ошибки загрузки выводятся в терминал команды, сессия продолжает работать со старой версией плагина.
4. Ctrl+C убирает `--dev`, возвращается установленная версия.

С `--watch-build` команда сама запускает `cargo build --target wasm32-…` для плагина при изменении исходников.

## Поверхности

| Поверхность | Назначение |
|---|---|
| `touchbar` через `touchbard` | рабочий режим |
| `touchbar` в окне симулятора | разработка без железа |
| `headless` | `render`, `replay --png`, эталонные кадры в тестах |
| `window` | после v1: окно на сенсорном мониторе ([16-surfaces.md](16-surfaces.md)) |

## Управление сессией (этап 3)

Основной сокет — `$XDG_RUNTIME_DIR/touchbar/session-control.sock`. В родительском каталоге требуются права 0700 и UID пользователя; сокет создаётся с правами 0600. Обе стороны проверяют `SO_PEERCRED`. Сообщение — длина JSON в u32 LE, затем JSON: `version = 1` и `command` либо `reply`. Предел — 16 МиБ. Соединение обслуживает один запрос; одновременно обрабатываются до восьми клиентов, ожидание клиента ограничено пятью секундами.

```sh
touchbarctl --simulator status --json
touchbarctl --simulator dump -o replay.json
touchbarctl --simulator reload
touchbarctl sim fact display.brightness=0.4
touchbarctl sim fact app.id=org.gnome.Terminal
touchbarctl sim fact --unset app.id
touchbarctl sim theme light
```

`reload` подтверждает постановку в очередь; результат приёма и ошибки видны в `status`. Отклонённая перезагрузка сохраняет прежний каталог. `sim` разрешён только для сессии с `--desktop=fake`. Значение факта — JSON (скаляр, список строк или список записей со скалярными полями), обычный не заключённый в кавычки текст тоже принимается. Для удаления используется `--unset`.

`status --json` содержит снимок ядра (`core`), диагностику последней попытки загрузки (`load_issues`), время последних вызовов действующих экземпляров (`last_calls`), p50/p99 последних 512 кадров и вызовов wasm (`metrics`), последние записи журнала (`logs`). До первого измерения процентили равны null. Сведения о владельце и recovery добавятся вместе с `touchbard` на этапе 4.

`dump` сохраняет приватный файл сессии и выводит путь. `-o` копирует его в указанный файл с правами 0600. Офлайн `render` по-прежнему не требует сокета.
