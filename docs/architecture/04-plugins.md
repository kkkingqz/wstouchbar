# Плагины

Плагин — единица поставки любого содержимого Touch Bar. Плагины доверенные: прав, согласий, подписей и установки пакетов нет.

## Состав

Плагин может содержать любую комбинацию частей:

| Часть | Файлы | Назначение |
|---|---|---|
| `logic` | `logic.wasm` | Модуль логики. Один модуль обслуживает несколько наборов (см. [05-logic.md](05-logic.md)) |
| `sets` | `sets/*.toml` | Наборы: раскладка элемента, варианты по ширине, панели |
| `profiles` | `profiles/*.toml` | Профили (см. [08-profiles.md](08-profiles.md)) |
| `categories` | `categories.toml` | Правила категорий приложений |
| `bindings` | `bindings.toml` | Привязки нажатий по умолчанию (см. [09-bindings.md](09-bindings.md)) |

Наборы без логики допустимы: тогда используются только встроенные виджеты и действия, например `key`.

Обработчики действий логики, привязки к её состоянию и `persist` требуют поставщика логики; их наличие в наборе без логики — ошибка проверки каталога.

## Манифест

```toml
# plugins/controls/plugin.toml
id = "controls"                 # [a-z0-9-], уникален среди плагинов
version = "1.0.0"
api = "1"                       # версия контракта логики и форматов
name = "System Controls"
description = "Volume, brightness and microphone"
logic = "logic.wasm"            # необязательно
requires = []                   # плагины, на наборы которых ссылаются профили этого плагина

[[sets]]
id = "volume"
file = "sets/volume.toml"

[[sets]]
id = "brightness"
file = "sets/brightness.toml"

[[assets]]
id = "speaker"
file = "assets/speaker.svg"
kind = "symbolic-svg"
width = 32
height = 32

# [[profiles]]                  # профили объявляются так же (D85)
# id = "default"
# file = "profiles/default.toml"
```

Ссылки между плагинами пишутся как `plugin/id`: `controls/volume`, `profile-media/media`. Если плагин из `requires` отсутствует или выключен, слоты с его наборами остаются пустыми, а профиль продолжает работать. Это видно в `touchbarctl status` и `explain`.

## Наборы

Формат переносится из `touchbar-set-config` исходного проекта, валидация становится строже (A11: `canvas` требует `canvas_from`). Манифест и наборы разбирает `touchbar-sets`: схема целиком, проверки и преобразование в `SetSpec` для ядра. Атрибуты раскладки в `SetSpec` не попадают, их читает рендер (D66). Узлы раскладки:
- контейнеры: `row`, `column`, `stack`, `responsive` (варианты по ширине), `repeat` (по записям состояния);
- элементы: `button`, `text`, `icon`, `image`, `slider`, `meter`, `progress`, `scrubber`, `canvas`, `shader-effect`;
- промежутки: `fixed-space`, `flexible-space`;
- новые: `key` (клавиша из `SystemKey`) и `key-row` (ряд клавиш одинаковой ширины).

Размеры задаются относительно поверхности ([16-surfaces.md](16-surfaces.md)). Число без единицы — это базовая единица `u`, по умолчанию 1 % короткой стороны поверхности (у Touch Bar — высоты). Автор набора может явно выбрать `"N%w"` или `"N%h"` для отдельного значения или переопределить `u` в разделе `[units]`. Пикселей нет, поэтому одни и те же наборы работают на Touch Bar разной длины и на других поверхностях.

Привязка к состоянию: поля `*_from` (`text_from`, `value_from`, `enabled_from`, `selected_from`, `visible_from`, `symbol_from`, `canvas_from`). Узел с `visible_from = false` **не участвует** в раскладке (A7). Обработчики: `on_pressed`, `on_activate`, `on_long_pressed`, `on_value_changed`, `on_selected`, `on_released`, `on_cancelled` — имя действия логики. `on_selected` допустим только у `scrubber`: при отпускании над элементом доставляет `Selected` с его `record_key`, согласно D47; действие должно объявлять этот вид события. Панели: `[[panels]]` с обязательной локальной раскладкой `[panels.layout]`, ширинами, `dismiss_on_selection` и `principal_item`, ссылки на них через `expanded_panel` и `press_and_hold_panel`. При `on_long_pressed` или `press_and_hold_panel` обязателен явно заданный положительный `hold_ms`; отсутствие или ноль отвергаются как InvalidWidget.

Виджеты панели используют состояние и действия одного экземпляра логики владельца (D48/D76). `principal_item` указывает на строковый `id` виджета этой панели. Старые `items` и `element.item`, ссылающиеся на другие наборы, отвергаются.

Набор F-клавиш плагина `system` целиком декларативный. Esc добавляется одной строкой:

```toml
# plugins/system/sets/fkeys.toml
version = 1
id = "fkeys"
label = "Function keys"

[layout]
kind = "key-row"
keys = [
  # { key = "esc", width = 150 },
  { key = "f1" }, { key = "f2" }, { key = "f3" }, { key = "f4" },
  { key = "f5" }, { key = "f6" }, { key = "f7" }, { key = "f8" },
  { key = "f9" }, { key = "f10" }, { key = "f11" }, { key = "f12" },
]
```

## Реализованная схема этапа 2

`SetFile::from_toml` и `PluginManifest::from_toml` отвергают неизвестные поля, недопустимые деревья и превышение бюджета. Ошибка содержит файл, путь свойства и строку. `SetFile::from_toml_with_description` дополнительно сверяет все привязки состояния и действия с wasm `describe`, включая свойства, которые нужны только рендеру. `to_spec(&manifest)` проецирует взаимодействия в ядро; полное дерево сохраняется в `SetFile` для этапа 3.

Строковый `id` задаётся интерактивным узлам с обработчиками. Идентификаторы уникальны внутри набора, включая варианты и панели. Для безымянных узлов при проекции генерируются стабильные `auto-layout-N`, без коллизий с явными id. Старые числовые `widget_id` не принимаются. Длины пишутся числом или строкой `"20u"`, `"20%w"`, `"20%h"`; объект `{ u = ... }` для длины не поддерживается.

В `plugins/controls/sets` перенесены volume, microphone и brightness. Узкий вариант громкости и яркости открывает локальную панель нажатием или удержанием 420 мс; широкий содержит ползунок. При исходной высоте 60 px размер пересчитан в u делением на 0,6. Battery и power-profile запланированы после v1. Рендер и выбор responsive-варианта относятся к этапу 3.

## Поиск плагинов

Каталоги просматриваются по порядку. При совпадении `id` побеждает первый найденный плагин целиком, без слияния частей:

1. `--plugins <dir>` (или `--dev <dir>`) (dev-режим, см. [11-tooling.md](11-tooling.md));
2. `$XDG_DATA_HOME/touchbar/plugins` (`~/.local/share/touchbar/plugins`);
3. `/usr/local/share/touchbar/plugins`;
4. `/usr/share/touchbar/plugins`.

Чтобы изменить поставляемый плагин, его копируют к себе и правят копию.

## Конфигурация пользователя

`$XDG_CONFIG_HOME/touchbar/config.toml` хранит только выбор, но не содержимое:

```toml
disabled = ["profile-media"]

[profile-for]                      # для всех поверхностей
"category:browser" = "my-browser-profile/browser"   # при конфликте профилей
"app:org.mozilla.firefox" = "my-firefox/firefox"

[profile-for."window:main"]        # только для одной поверхности (после v1)
"category:browser" = "my-window-profiles/browser"

[app."org.gnome.Rhythmbox3"]
categories = ["media-player"]      # заменяет автоопределение для одного приложения

[logic]
time-limit-ms = 50                 # жёсткий предел вызова логики
```

Лимит `[logic] time-limit-ms` применяется только при старте (D100). Его изменение отклоняет reload целиком с сообщением о необходимости перезапуска.

Ресурсы `[[assets]]` объявляют `id`, безопасный относительный `file`, `kind` (`png` или `symbolic-svg`) и размеры растра `width`/`height` в пикселях (D101). PNG проверяется на совпадение размеров, SVG растрируется в эти размеры. PNG сохраняет исходные цвета, symbolic-svg использует маску цвета интерфейса. `asset` и `asset_from` ссылаются на объявленные идентификаторы. Symbolic SVG — самодостаточные векторные данные: внешние и встроенные изображения (`image`/`feImage`) не разрешаются, попытка их загрузки отклоняет ресурс с диагностикой. Локальные векторные ссылки (`use` на элементы того же SVG) сохраняются; растры объявляются отдельными PNG-ресурсами.

## Загрузка и проверка

Загрузчик работает в рабочем потоке. Он читает все каталоги, разбирает манифесты и файлы, проверяет ссылки, компилирует wasm (с кешем скомпилированных модулей в `$XDG_CACHE_HOME/touchbar/wasm`) и выдаёт ядру `Catalog`. `Runtime::compiler()` возвращает Send-компилятор с тем же Engine и Linker; `Compiler::prepare(bytes)` проверяет ABI и готовит Send `PreparedModule` в рабочем потоке. В потоке сессии `Runtime::install(plugin, revision, Result<PreparedModule, LoadError>)` только устанавливает результат: компиляции и вызовов гостя здесь нет. Ошибки подготовки кешируются по той же неизменяемой паре, что успешные модули. Модуль другого Engine отвергается. `load_module` оставлен как синхронное удобство для тестов; загрузчик сессии использует prepare/install. `Runtime::describe(plugin, revision)` и `create` используют общий кеш описания: гостевой describe выполняется один раз на ревизию.

В `PluginSpec.revision` загрузчик передаёт стабильную ревизию содержимого: она меняется при изменении TOML или wasm и сохраняется при повторном чтении тех же файлов. Это не `version` манифеста и не счётчик команды `reload`. Ядро не читает файлы и не вычисляет хеши (D44).
- **Плагин с ошибкой при первом запуске** пропускается целиком, ошибка видна в журнале и в `status`. Остальные плагины загружаются. При reload ошибка любого плагина отклоняет обновление целиком (D94).
- **Конфликт профилей.** Два включённых плагина объявляют профиль для одной цели (`app:…` или `category:…`), и в `profile-for` выбор не сделан. Оба профиля для этой цели не используются, а `status` и `doctor` показывают конфликт. Молча выбирать первый попавшийся нельзя.
- **Категории с одинаковым `id`** из разных плагинов объединяются: так можно дополнять списки, например браузеров.
- **Перезагрузка** по inotify в каталогах плагинов и `config.toml` или по `touchbarctl reload`. Новый каталог заменяет старый целиком, только если он загрузился. Ошибка чтения, разбора, подготовки или проверки любого плагина либо конфигурации при перезагрузке оставляет прежние каталог, документы рендера, ревизии логики и конфигурацию и не завершает сессию (A12, D94). Исправные части такого обновления отдельно не принимаются.

После принятия каталога оболочка вызывает `Runtime::retain_modules`, оставляя только его пары `(plugin, revision)`. Это удаляет и скомпилированные модули, и ошибки старых загрузок; работающие Store сохраняют свой код и продолжают отвечать. Удалённая ревизия не может создавать новые экземпляры до повторной подготовки и установки. При отклонённом reload очистка ориентируется на прежний принятый каталог (A12), а не на кандидат.

## Плагины первой версии

Лежат в `plugins/` репозитория, у каждого свои тесты:

| Плагин | Содержимое |
|---|---|
| `system` | набор `fkeys`, привязка «Fn удерживается → слой `system/fkeys`» |
| `controls` | логика, наборы `volume`, `brightness`, `microphone` и панель громкости |
| `media` | логика, наборы `transport`, `timeline` |
| `browser` | логика, набор `navigation` (назад, вперёд, обновить через `desktop.shortcut`) |
| `profile-default` | профиль `default` |
| `profile-browser` | категория `browser`, профиль для `category:browser` |
| `profile-media` | категория `media-player`, профиль для `category:media-player` и вариант для `category:browser` при `media.active` |

## Загрузчик сессии (S7)

`LoadRequest::standard` добавляет `--plugins` перед путями XDG и системными. Внутри пути каталоги сортируются; первая parseable идентичность резервируется даже при ошибке другого поля манифеста, поэтому повреждённую копию не заменяет затенённый плагин.

`Worker` читает ограниченные файлы и готовит wasm через общий Compiler. Он допускает один запрос в очереди и один ожидающий результат; `submit` не блокирует поток сессии и сообщает о заполнении. Оболочка объединяет повторные запросы reload. `Loader::accept` устанавливает готовые модули, сверяет описание со всеми наборами и проверяет каталог через чистый `Core::check_catalog`. После приёма оболочка публикует Catalog и Documents вместе. При отказе сохраняются их прежние значения и конфигурация, модули очищаются по прежнему каталогу.

При первоначальной загрузке ошибка плагина удаляет его целиком, затем зависимости проверяются снова. Синтаксическая ошибка пользовательского файла сохраняет конфигурацию старта; при семантической ошибке выбора/привязок загрузчик один раз повторяет проверку с конфигурацией старта и без пользовательских привязок. Такая попытка допустима только при совпадении disabled с уже просканированными каталогами; иначе кандидат отвергается. Конфликты профилей и отсутствующие requires остаются диагностикой.

Пределы чтения: TOML/SVG 256 КиБ, wasm 16 МиБ, PNG 4 МиБ, всего 64 МиБ и 1024 файла на плагин. Растры одного плагина — не больше 16M пикселей, один ресурс — до 2048×2048. Читаются только обычные файлы; открытие неблокирующее, поэтому FIFO отвергается без ожидания писателя. Ревизия включает пути и точные байты манифеста, wasm, объявленных наборов, профилей, изображений и bindings.toml, в отсортированном порядке.

`ReloadWatcher` следит за каталогами плагинов рекурсивно и родителями пользовательских файлов, включая атомарную замену. Он учитывает канонический путь и inode, следует симлинкам без циклов и ограничен 4096 каталогами. `poll` принимает монотонное время, `deadline` задаёт конец объединения событий за 200 мс либо повтор обслуживания через 1 с. Недоступные/исчезнувшие подкаталоги и превышение бюджета наблюдения дают ограниченную диагностику, сохраняют действующие и родительские watches и не завершают сессию. После восстановления наблюдение пересобирается и запрашивается загрузка. Фатальными остаются ошибки самого транспорта inotify. `AsFd` позволяет включить watcher в цикл сессии.

Офлайн `touchbarctl render` загружает явно выбранный набор и ресурсы без чтения/компиляции wasm. Доступен и выключенный пользователем плагин, чтобы его можно было проверить до подключения. Init и эффекты не исполняются: нужные значения задаются через JSON StatePatch в `--state`.
