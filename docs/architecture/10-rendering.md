# Рендер

Переносим всё из `touchbar-ui`, `touchbar-layout` и рендера `touchbar-sessiond` исходного проекта. Меняется одно: автоматы жестов (`gesture.rs`) и панелей (`presentation.rs`) переезжают в `touchbar-core`. В UI остаются отрисовка и построение геометрии элементов.

## Конвейер

```
Scene (из ядра) + документы каталога ──▶ touchbar-scene: дерево и Layout
                ──▶ touchbar-layout / taffy: раскладка в физических пикселях
                ──▶ touchbar-ui: CPU-текст, SVG, примитивы и DisplayList
                ──▶ touchbar-gl: GLES, текстуры и программы WGSL → GLSL
                ──▶ сравнение с прошлым кадром по колонкам на GPU
                ──▶ буфер swapchain ──▶ FrameDamage ×≤8 + FrameReady ──▶ touchbard (FB_DAMAGE_CLIPS)
```

## Что переносится

| Часть | Источник |
|---|---|
| Узлы: контейнеры, кнопки, ползунки, индикаторы, scrubber, canvas, shader-effect, motion | `touchbar-ui` |
| Палитра, роли цветов, темы light/dark, акцент | `touchbar-ui/palette.rs` |
| Символы и ресурсы (SVG, PNG) | `touchbar-ui/symbols.rs`, `asset.rs` |
| Раскладка профиля: слоты, группы, `equal-width`, промежутки, панели | `touchbar-layout` |
| Выбор GPU: `TOUCHBAR_RENDER_NODE`, затем `boot_vga`, затем первый узел. EGL `EGL_EXT_platform_device`, surfaceless как запасной вариант | `touchbar-sessiond/gpu.rs` |
| Частичная перерисовка: сравнение колонок шейдером, кадр не отправляется, если ничего не изменилось | `touchbar-sessiond/gpu.rs` |
| Ориентация: сессия рисует сразу в физическую раскладку буфера (portrait 60×N у `appletbdrm`), поворот в GL, без копирования в root | заголовок swapchain v1 |
| Проверка попадания: если касание не попало в элемент, выбирается ближайший виджет в той же колонке | `touchbar-ui` (6e9cf8b) |

Раскладка и построение кадра детерминированы и не используют GL: их результат — сериализуемый список примитивов и карта попаданий. GL только рисует этот список. Обычные тесты сверяют список точно, PNG-эталоны рисует тот же GL-рендер на Mesa llvmpipe в отдельном прогоне (D79).

Перерисовываются только экземпляры, у которых изменилось состояние, видимость, вариант `responsive` или тема. Раскладка пересчитывается только при смене сцены и ширины слотов.

## Несколько поверхностей

Одно GPU-устройство и общий кеш шрифтов, текстур и шейдеров. У каждой поверхности своя цель отрисовки и своё расписание кадров. Поверхности рисуются по очереди в главном потоке ([16-surfaces.md](16-surfaces.md)).

## Кадры

- **По требованию.** Кадр строится только после изменения. Анимации и `motion` запрашивают кадры, пока идут, но не чаще 60 в секунду.
- **Не больше одного кадра в работе:** следующий начинается после `BufferReleased` и `FrameDone`.
- **После смены режима или переподключения** первый кадр полный (без `FrameDamage`).

## Единицы

Наборы и профили задают размеры в базовых единицах `u` (по умолчанию 1 % короткой стороны поверхности), а при явном выборе автора — в `%w` и `%h`. Цепочка `[units]` (набор → профиль → поверхность) разрешается здесь же. Перевод в пиксели и округление до целых физических пикселей делаются только здесь, при раскладке ([16-surfaces.md](16-surfaces.md)). Ядро получает карту попаданий уже в пикселях. Эталонные кадры в тестах снимаются на нескольких размерах поверхности: 2008×60, 2170×60 и окно.

## Темы

`appearance.scheme` и `appearance.accent` из API рабочего стола задают палитру. Если фактов нет, используются тёмная схема и системный акцент по умолчанию. Плагины получают тему в `context-changed` и через роли цветов в наборах. Логике менять цвета не нужно.

## Шрифты

cosmic-text с системными шрифтами через fontconfig. Шрифт интерфейса по умолчанию берётся из GNOME (`org.gnome.desktop.interface font-name`, факт бэкенда), запасной вариант — Cantarell или Inter. Значки — собственный набор SVG-символов.

## Контракт кадра (D96)

DisplayList содержит команды в порядке рисования и таблицу ресурсов со стабильными ключами: растровые маски/изображения и исходники шейдеров. Команды ссылаются на эту таблицу. В памяти неизменяемые данные разделяются через Arc, при сериализации включаются в пакет целиком. Восстановленный JSON можно рисовать без скрытого хранилища ресурсов. GL кеширует текстуры и программы по ключам ресурсов.

## Пиксельная композиция

`touchbar-layout` получает уже переведённые в физические пиксели размеры. Слоты сохраняют `minimum`, `width`, `maximum` корня набора. Положительный `grow` задаёт долю свободной ширины вместе с весами `flexible-space`; при достижении максимума остаток делится между остальными участниками. Скрытые слоты в этом распределении не участвуют. Группы могут содержать слоты, вложенные группы и промежутки. В `equal-width` действует общий допустимый интервал ширины прямых потомков. Естественная группа внутри более широкой ячейки `equal-width` сохраняет исходное заполнение до максимумов потомков, если явные веса роста не заданы.

По D98 базовая ширина корня набора — 266⅔u: 160 px при стандартной поверхности высотой 60 px. Без `minimum`, `maximum` и `grow` слот фиксирован; явная `width` заменяет базовую ширину. Наличие любого ограничения или `grow` включает flex: минимум по умолчанию 100u, максимум 100%w, вес роста 1. Явные значения заменяют соответствующие значения по умолчанию; база ограничивается интервалом минимума и максимума после перевода в пиксели.

Для `anchored` центр панели совпадает с горизонтальным центром исходного прямоугольника якоря, с ограничением по краям поверхности. По вертикали панель занимает высоту слота владельца. Ширина — `preferred_width`, ограниченная поверхностью; если `minimum_width` не помещается, раскладка возвращает ошибку. `region` и `full` используют заданные ядром области целиком (D50). Выбор responsive-представления сохраняет порядок полноты `minimal < compact < full`: выбирается самое полное из вариантов, для которых хватает ширины.

## Проекция сцены (S5)

`touchbar-scene::SceneRenderer` получает поверхность, `Scene`, неизменяемые `Arc<SetDocument>` принятого каталога, тему, `CpuPainter`, явный `Timestamp` и политику motion. Внутри нет часов и I/O. `Frame` содержит DisplayList, геометрию для Layout, флаг следующего кадра анимации и диагностику. Идентификаторы виджетов берутся из SetSpec, включая автоматически назначенные идентификаторы; числовые UI-идентификаторы остаются локальными.

Кеш дерева учитывает состояние, взаимодействия, единицы, тему, размеры слота и поверхности (проценты относятся к поверхности), а также идентичность принятого документа. Геометрия кешируется отдельно; изменение времени только сэмплирует примитивы. Таймлайн motion сохраняется при пересборке, пока его параметры не изменились. Символы разделяются между экземплярами; предупреждение о неизвестном имени выдаётся один раз. При удалении поверхности оболочка вызывает `remove_surface`.

`Loading` рисуется без содержимого, `Faulted` — заглушкой, `Hidden` не рисуется. Рисуется верхняя активная плоскость; Layout сохраняет границы экземпляров остальных плоскостей. Панель перекрывает свою область, её hits имеют плоскость Presentation. Локальная ошибка построения или подготовки растра возвращается в `Frame.faults` и рисуется заглушкой; оболочка передаёт её ядру через существующий InstanceFault.

Для синтетических сцен без документа профиля применяется линейная раскладка экземпляров. Пустой слот документированного профиля сохраняет ширину первого доступного документа кандидата (или базовую ширину D98), с единицами набора/профиля. Он присутствует в `named_slots` без InstanceId; Input::Layout получает только реальные экземпляры. У слота с `visible_from=false` или не поместившегося слота bounds отсутствуют.

По D99 `scrubber` использует обязательные `repeat_from`, `repeat_key`, `template`. Шаблон содержит только визуальные узлы; `value/value_from` запрещены. Геометрия записей передаётся до прокрутки, а рисование использует offset/highlighted/selected ядра. По умолчанию ширина ячейки 100u (60 px при стандартных единицах), явная width шаблона имеет приоритет. Размеры, padding и spacing округляются до физических пикселей; ячейки нулевой ширины не рисуются и не выбираются. Повторения требуют уникального непустого текстового ключа длиной до 128 байт.

Сохраняются бюджеты исходного host: 256 узлов документа, 512 расширенных узлов UI, глубина 32, текст 16 КиБ на построение; canvas — 512 команд, 2048 точек, 256 сегментов пути и 512 треугольников. Размер текста ограничен 512 физическими пикселями до shaping; это оставляет запас для масштабирования оконной поверхности.

Эталоны S5 хранят точные команды и геометрию, а для растров — ключ содержимого и размеры. Ключ учитывает все байты растра; сами RGBA-массивы не дублируются в каждом эталоне. Сериализация полного пакета проверяется тестами DisplayList. S6 использует эти кадры для сравнения PNG.
