# Протокол touchbard ↔ сессия (v2)

## Транспорт

- **Сокеты.** Сессия подключается к `/run/touchbar/session.sock`, `touchbarctl` — к `/run/touchbar/control.sock`. `session.sock` — `SOCK_SEQPACKET`: одна датаграмма содержит одно сообщение. `control.sock` — `SOCK_STREAM` с кадрами JSON (см. ниже).
- **Права.** Сокеты принадлежат root, права 0666. Доступ решают `SO_PEERCRED` и logind; группа и sysusers не нужны. Не больше 16 соединений без рукопожатия, срок рукопожатия — 1 с.
- **Формат.** Сообщения фиксированного размера, 32 байта, little-endian. Формат перенесён из v1 исходного проекта:

```
0      8        10      12      16          24      28      32
| magic | version | kind | value | payload   |   x   |   y   |
 "TBARMSG2"  u16     u16    u32     u64         i32     i32
```

- **Swapchain.** Буферы передаются одним сообщением с заголовком 48 байт (`TBARHWD2`) и 2–3 дескрипторами через `SCM_RIGHTS`. Заголовок описывает размеры, pitch, физическую ориентацию и флаги.
- **Нарушения.** Любое нарушение формата (неизвестный `kind` для этой версии, значения вне диапазона, лишние дескрипторы, неполная датаграмма) закрывает соединение. Никаких частичных разборов и попыток восстановиться.

## Рукопожатие

```
сессия                               touchbard
  Hello{version=2} ───────────────────▶ проверка UID и активной сессии seat0
                   ◀─────────────────── ModeChanged{native} или Revoked{reason}
       ожидание native/recovery: без таймаута (D124)
       после готовности display:
                   ◀─────────────────── Welcome{caps, width, height, mm}
                   ◀─────────────────── ModeChanged{display}
                   ◀─────────────────── Swapchain (заголовок + fd)
  WatchKey ×N     ───────────────────▶
```

Лимит рукопожатия 1 с относится к получению `Hello`, не к появлению DRM. Размеры не угадываются в native. Новый swapchain получает новое поколение; после переподключения сессии буферы создаются заново, в пределах grace — без USB-переключения native/display. Пока уведомление о текущем Display не отправлено, демон не исполняет новые нажатия и не передаёт касания.


`caps` — битовая маска возможностей `touchbard`: частичная перерисовка (`FrameDamage`), список поддерживаемых `SystemKey`. Неизвестные биты игнорируются. Ширина и высота задаются в логических пикселях полосы и не зашиваются в код: у MacBookPro16,1 Touch Bar 2008×60, у моделей без физического Esc он шире.

## Сообщения сессии

| kind | Поля | Смысл |
|---|---|---|
| `Hello` | `value` = версия | Первое сообщение. Проверка владельца по UID и активной сессии seat0 — в [01-processes.md](01-processes.md) |
| `FrameDamage` | `payload` = x\|y<<16\|w<<32\|h<<48, физические пиксели | До 8 штук перед `FrameReady`. Если их не было, обновлён весь кадр |
| `FrameReady` | `value` = индекс буфера, `payload` = номер кадра | Буфер готов к выводу |
| `Key` | `value` = `SystemKey`, `x` = фаза (pressed/released) | Ввести клавишу через uinput. Автоповтор делает ядро (`EV_REP` у uinput-устройства) |
| `WatchKey` | `value` = код из закрытого списка, `x` = enabled (0/1) | Включить или выключить наблюдение. Сессия отправляет разницу списков `WatchKeys` ядра (D122) |
| `Backlight` | `value` = верхний предел 0…65535 (нормированная доля) | Ограничение яркости от сессии, например на экране блокировки |

`SystemKey` — закрытый набор. Кроме ключей v1 (яркость, подсветка клавиатуры, медиа, громкость, Search) в нём F1–F12 и Esc. Преобразование в коды evdev делается только в `touchbard`, произвольный ввод клавиш через протокол невозможен.

`WatchKey` принимает только клавиши, которые не печатают символы: Fn, Esc, модификаторы, F1–F12. Так через протокол нельзя устроить клавиатурный перехватчик.

## Сообщения touchbard

| kind | Поля | Смысл |
|---|---|---|
| `Welcome` | `value` = caps, `x`,`y` = ширина и высота в пикселях, `payload` = ширина\|высота<<32 в сотых долях мм | Ответ на `Hello`. Физический размер нужен для порогов жестов ([16-surfaces.md](16-surfaces.md)) |
| `Revoked` | `value` = причина: `NotActive`, `SessionInactive`, `Replaced`, `Version`, `Shutdown` | Последнее сообщение перед закрытием соединения |
| `ModeChanged` | `value` = `display`/`native`, `payload` = причина: владелец, recovery, блокировка экрана, сон, ошибка | Смена режима. В `native` сессия не рисует |
| `Touch` | `value` = фаза (down/move/up/cancel), `payload` = `ContactId`, `x`,`y` = координаты в логических пикселях | Касание |
| `KeyEvent` | `value` = код, `x` = фаза | Событие отслеживаемой клавиши (`WatchKey`) |
| `BufferReleased` | `value` = индекс, `payload` = номер кадра | Буфер снова свободен для рисования; это не подтверждение показа |
| `FramePresented` | `value` = индекс, `payload` = номер кадра, `x` = длительность commit в мкс | Кадр показан. Только это сообщение завершает `FrameDone` сессии |

**ContactId.** Номер касания назначает `touchbard`. Это ненулевое `u32` (`NonZeroU32`), значения растут монотонно в пределах соединения; при исчерпании пространства идентификаторов соединение закрывается. Tracking ID ядра наружу не уходит: оно начинает нумерацию с 0, и это было причиной Б4 в исходном проекте.

**Cancel от touchbard.** Если touchbard сам прерывает касание (смена режима, отзыв, recovery, исчезло устройство), он отправляет `Touch{cancel}` для каждого активного касания до `ModeChanged` или `Revoked`.

Перед native, `Revoked` и закрытием соединения `touchbard` независимо отпускает все введённые владельцем клавиши (D43). Сессия завершает свой учёт релизами, но после `Revoked` их доставка уже не требуется для отпускания uinput.

## Управление потоком

Номер кадра положительный и строго возрастает в пределах принятой swapchain. Нулевой номер отклоняется до передачи в DRM; его не принимает и поддельный демон в testkit.

- Не больше одного кадра ожидает `FramePresented` (D125). Показанный буфер остаётся занят до `BufferReleased`, но учитывается отдельно от ожидающего кадра. Сессия рисует только в буфер, который получила через `BufferReleased` или ещё ни разу не отправляла.
- Касания `move` объединяются: если очередь к сессии растёт, промежуточные `move` одного касания отбрасываются, а `down`, `up` и `cancel` не отбрасываются никогда.
- Если очередь сессии переполнена, `touchbard` отзывает локальный ввод и отключает её. Основной предел — 256 записей; завершающие cancel и Revoked имеют ограниченный резерв (до 32 активных контактов). Уже принятые down/up/cancel сохраняют порядок; move одного контакта объединяются.
- На отправку завершающей очереди отводится не больше 1 с: недоступный получатель не удерживает соединение бессрочно. EOF требует от сессии локально отменить все её касания.
- Номера кадров растут в пределах swapchain. Неверный индекс, повторная отправка занятого буфера, второй кадр до FramePresented, лишний или выходящий за буфер damage — ошибка протокола.
- ContactId не переиспользуется в одном соединении: при исчерпании u32 соединение закрывается. Одновременно принимается до 32 контактов.

## Управляющий сокет

Используется `touchbarctl`. Одно соединение — один запрос и один ответ. Кадр: длина тела `u32` little-endian, затем JSON, от 1 байта до 64 КиБ. Кодек общий с `touchbar-control`, где сокет сессии сохраняет предел 16 МиБ. Длина проверяется до выделения тела, сериализация останавливается по лимиту.

Версия JSON-управления — 1, независимо от бинарного v2. Запрос: `{"version":1,"command":{"kind":"status"}}`, `{"version":1,"command":{"kind":"set-mode","mode":"native"}}` или `reload`. Неизвестные поля и варианты запрещены. Ответ: `{"version":1,"reply":{"kind":"ack"}}`, `status` с объектом `data` или `error` со строкой `data`. Обе стороны проверяют версию.

| Запрос | Кто может | Смысл |
|---|---|---|
| `Status` | root или пользователь активной сессии seat0 | Режим, владелец, recovery, подсветка, версия |
| `SetMode{native\|display}` | то же | `native` включает recovery, `display` выключает его |
| `Reload` | только root | Перечитать `touchbard.toml` |

Сон обрабатывается напрямую через logind `PrepareForSleep` и delay-inhibitor, команд сна в управляющем протоколе нет (D105).

## Точные значения и ограничения

Все неиспользуемые поля равны нулю. Кодеки направлений не принимают сообщения другого направления.

| kind (число) | Сообщение |
|---|---|
| 1, 2 | FrameReady, BufferReleased |
| 8, 9, 10, 11, 12, 13 | Key, FrameDamage, Hello, Welcome, Revoked, ModeChanged |
| 14, 15, 16, 17, 18 | Touch, KeyEvent, WatchKey, Backlight, FramePresented |

`SystemKey`: яркость 1/2, подсветка клавиатуры 3/4, PreviousSong 5, PlayPause 6, NextSong 7, Mute 8, VolumeDown 9, VolumeUp 10, MicrophoneMute 11, Search 12, Esc 20, F1–F12 21–32. `WatchKey`: Fn 1, Esc 2, LeftShift/RightShift 3/4, LeftControl/RightControl 5/6, LeftAlt/RightAlt 7/8, LeftMeta/RightMeta 9/10, F1–F12 21–32.

Фазы клавиш: released 0, pressed 1. Фазы касания: down 0, move 1, up 2, cancel 3. `Mode`: native 0, display 1. Причины `ModeChanged`: owner 0, recovery 1, locked 2, sleep 3, error 4. Причины `Revoked`: NotActive 1, SessionInactive 2, Replaced 3, Version 4, Shutdown 5.

Индекс буфера 0…2; автомат дополнительно проверяет число буферов и их занятость. `ContactId` — 1…u32::MAX. `FramePresented.x` — 0…i32::MAX мкс, от подачи commit до события завершения, без ожидания в очереди и IPC (D107). `Backlight`: 0 гасит, 65535 не ограничивает; физические уровни драйвера выбирает демон.

Заголовок swapchain: magic в 0…8, version u16 в 8, buffer_count u16 в 10; logical width/height u32 в 12/16, physical width/height в 20/24, format в 28, pitch в 32, flags в 36, buffer_size u64 в 40. Размеры 1…16384, физическая геометрия совпадает с логической или повёрнута на четверть оборота. Формат — XRGB8888 (`0x34325258`); pitch кратен 4, не меньше строки и не больше 65536; buffer_size не меньше pitch × physical_height и не больше 1 ГиБ. Флаг 1 означает поддержку FrameDamage, остальные запрещены. Ровно 2–3 дескриптора, все принимаются с `CLOEXEC`; при любой ошибке полученные дескрипторы закрываются.

`FrameDamage` — изменения относительно предыдущего показанного кадра, а не предыдущего содержимого выбранного буфера. Полноту содержимого буфера обеспечивает сессия (D108).

## Версионирование

Версия протокола — `version` в каждом сообщении. `touchbard` поддерживает ровно одну версию, а сессия с другой получает `Revoked` с причиной `Version`. Обе части ставятся одним пакетом, поэтому совместимость между версиями не нужна. Расширение возможностей внутри версии идёт только через `caps`.
