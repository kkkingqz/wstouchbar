# Поверхности и единицы

## Поверхность

Поверхность — то, на чём сессия рисует и откуда получает касания. Touch Bar — только один из её видов. Содержимое (наборы, профили, логика) от вида поверхности не зависит.

| Вид | Статус | Кадры | Касания | Клавиши для привязок | Ввод клавиш | Режимы, подсветка |
|---|---|---|---|---|---|---|
| `touchbar` | v1 | swapchain `touchbard` | `touchbard` | `touchbard` (`WatchKey`) | uinput в `touchbard` | есть |
| `window` | запланирован, не реализуется в v1 | EGL-поверхность окна Wayland | `wl_touch`, мышь | бэкенд рабочего стола или жесты касанием | бэкенд рабочего стола (команда `key`) | нет |
| `headless` | v1 | PNG в памяти | тесты | тесты | журнал | нет |

Симулятор разработчика ([11-tooling.md](11-tooling.md)) — это окно, которое изображает поверхность вида `touchbar`: размеры и плотность Touch Bar, а клавиши и Fn берутся с клавиатуры. Будущая поверхность `window` — отдельный вид для работы на сенсорном мониторе.

### Описание поверхности

```rust
pub struct SurfaceInfo {
    pub id: SurfaceId,
    pub kind: SurfaceKind,          // Touchbar | Window | Headless
    pub width_px: u32,
    pub height_px: u32,
    pub px_per_mm: f32,             // плотность для порогов жестов
    pub caps: SurfaceCaps,          // modes, backlight, watch_keys, inject_keys, damage
}
```

Плотность берётся так:
- **`touchbar`:** из физического размера в `Welcome` ([02-protocol.md](02-protocol.md)). `touchbard` берёт его из DRM-коннектора, а если коннектор размер не сообщает, из таблицы моделей по DMI (`MacBookPro16,1` и т. д.).
- **`window`:** из физического размера `wl_output` и масштаба окна.
- **`headless`:** из параметров теста.

### Поверхность в ядре

- **Входы и выходы ядра** адресуют поверхность через `SurfaceId`: `SurfaceAdded(SurfaceInfo)`, `SurfaceChanged`, `SurfaceRemoved`, `Touch`, `Layout`, `Mode`, `Render`. Касание идентифицируется парой `(SurfaceId, ContactId)`.
- **У каждой поверхности** своя сцена, свой выбор профиля, свои слои и панель (подробнее — «Несколько поверхностей» ниже).
- **Свойства поверхности — это факты.** Профиль для поверхности выбирается по общим фактам плюс фактам этой поверхности:

| Факт | Пример |
|---|---|
| `surface.kind` | `touchbar` |
| `surface.width-mm`, `surface.height-mm` | физический размер в мм |
| `surface.aspect` | ширина / высота, у Touch Bar 16" — около 33 |

  Так для окна можно сделать отдельную раскладку: `when = { "surface.kind" = "window" }`.
- **Возможности (`caps`).** Ядро не выдаёт команд, которые поверхность не поддерживает. `SendKey` без `inject_keys` у поверхности уходит в бэкенд рабочего стола (команда `key`). Если и бэкенд не умеет, действие возвращает `unsupported`. `Mode` и `Backlight` бывают только у поверхностей с `modes` и `backlight`.
- **Привязки.** Действие `layer` применяется к поверхности, с которой пришла клавиша (подробнее — ниже).

### Несколько поверхностей

Сессия работает с любым числом поверхностей одновременно (до 8), например с Touch Bar и окном на сенсорном мониторе. В v1 реально подключается только Touch Bar, но ядро, конфигурация, рендер и тесты с самого начала рассчитаны на несколько поверхностей. Несколько поверхностей проверяются уже в v1: симулятор может изображать поверхности любого вида ([11-tooling.md](11-tooling.md)).

- **Имена.** Помимо `SurfaceId`, который живёт только во время работы, у поверхности есть постоянное имя `SurfaceName`: `touchbar` для Touch Bar, `window:<name>` для окон из конфигурации. Имена используются в `config.toml`, в привязках, в путях сохраняемого состояния, в `status`, `explain` и в дампах.
- **Откуда берутся.**
  - Touch Bar появляется, когда сессия стала владельцем в `touchbard`, и исчезает при отзыве или отключении. Режим `native` поверхность не убирает, а только переключает её `Mode`.
  - Окна (после v1) объявляются в `config.toml` и создаются бэкендом окон:

    ```toml
    [[surface.window]]
    name = "main"
    output = "DP-1"          # монитор
    edge = "bottom"          # край, к которому прикреплено окно
    height = "15mm"          # физический размер
    ```
- **Независимость (I12).** У каждой поверхности своя сцена, свой выбор профиля (общие факты плюс `surface.*`), слои, панель, касания, карта попаданий, режим и расписание кадров.
- **Экземпляры.** На каждой поверхности свои экземпляры, даже если набор тот же самый: у `controls/volume` на Touch Bar и `controls/volume` в окне своё состояние логики, видимость и панели. Общее системное состояние (громкость, трек) оба получают через подписки. Ключ экземпляра включает имя поверхности, сохраняемое состояние лежит в `<plugin>/<surface>/<slot>.json`.
- **Общие подписки.** Исполнитель объединяет одинаковые подписки разных экземпляров (тот же вид и параметры, например `audio.watch default-sink`): источник один, данные рассылаются всем подписчикам, а источник останавливается, когда отписался последний. Действия не объединяются: каждый запрос выполняется.
- **Привязки.** Действие слоя по умолчанию применяется к поверхности, с которой пришла клавиша: Fn с Touch Bar показывает F-клавиши только на Touch Bar. Клавиши от бэкенда рабочего стола действуют на поверхности без собственного источника клавиш. В привязке можно явно указать `surfaces = ["touchbar", "window:main"]` или `surfaces = "all"`.
- **Режимы и recovery** относятся только к поверхностям с `modes`, то есть к Touch Bar. Окна они не затрагивают.
- **Рендер.** Одно GPU-устройство, у каждой поверхности своя цель отрисовки (swapchain или EGL-поверхность окна). Поверхности рисуются по очереди в главном потоке, у каждой свои кадры, освобождение буферов и области перерисовки.
- **Профили по поверхностям.** Профили выбирают поверхность через `when = { "surface.kind" = … }`. Конфликты и явный выбор в `config.toml` задаются для каждой поверхности отдельно ([04-plugins.md](04-plugins.md)).

### Сессия без touchbard

Сессия не зависит от `touchbard`:
- **Нет Touch Bar** (другая модель, `touchbard` не установлен или не запущен): сессия работает с поверхностями других видов. В v1 это значит, что она ждёт подключения.
- **Сокет `touchbard` появился позже:** сессия подключается к нему, когда он появится (inotify на `/run/touchbar`).

Пользовательский юнит не требует `touchbard.service`.

## Поверхность `window` (запланирована)

В v1 не реализуется. Архитектура оставляет для неё место, а эти вопросы нужно решить при реализации:

1. **Фокус.** Окно не должно забирать фокус клавиатуры и становиться `app.id`, иначе шорткаты уйдут в него, а профиль сменится.
   - wlroots, KDE, Hyprland: `wlr-layer-shell`, слой `top` или `overlay`, `keyboard-interactivity = none`, прикрепление к краю монитора.
   - GNOME: layer-shell нет. Варианты: поверхность внутри Shell через наше расширение (оно показывает буфер сессии как актёр Clutter) или окно, которому расширение запрещает фокус. Требует исследования.
2. **Своё окно не попадает в факты фокуса**: бэкенд исключает его из `app.id`.
3. **Выбор монитора и края**, размер, автоскрытие. Настройки — в `config.toml`, раздел `[surface.window]`.
4. **Ввод.** Касания идут через `wl_touch`, мышь работает как один палец. У Wayland-окна нет глобальных клавиш. Привязки получают клавиши через бэкенд рабочего стола (расширение GNOME может отслеживать глобальные сочетания), либо слои переключаются триггерами касанием.
5. **Клавиши.** Ввод `SystemKey` (F-клавиши, медиа) идёт через виртуальную клавиатуру бэкенда рабочего стола.

## Единицы размеров

В наборах и профилях пикселей нет. Длина записывается в одной из единиц:

| Запись | Значение |
|---|---|
| `N` (число без единицы) или `"Nu"` | N **базовых единиц** `u` — единица по умолчанию |
| `"N%w"` | N процентов **ширины поверхности** |
| `"N%h"` | N процентов **высоты поверхности** |

### Базовая единица u

По умолчанию размер `u` вычисляется из размера поверхности: **1u = 1 % её короткой стороны**. У Touch Bar короткая сторона — это высота, поэтому 100u равны высоте полосы. На любой модели Mac и на окне любой формы пропорции элементов сохраняются, а оставшееся место по длинной стороне распределяет flex через безразмерные веса `grow` и `weight`.

Автор **может** выбрать единицу сам:
- явно записать отдельное значение в `%w` или `%h`, например `maximum = "40%w"`, чтобы элемент рос вместе с длиной полосы;
- переопределить размер `u` для своего набора или профиля:

```toml
[units]
u = "0.05%w"      # только через %w или %h поверхности
```

Размер `u` для длины внутри набора берётся по цепочке: `[units]` набора → `[units]` профиля, в котором набор размещён → значение поверхности по умолчанию. Для длин самого профиля цепочка начинается с профиля. **Профили v1 (`default`, `browser`, `media`) и их наборы `u` не задают** и используют значение поверхности.

### Правила

- Значения неотрицательные, дробные допускаются. `%w` и `%h` — не больше 100, `u` — не больше 10 000.
- Проценты считаются от всей поверхности, а не от родителя.
- В веса (`grow`, `weight`) записываются безразмерные числа, это не длины.
- Неизвестная единица (`"6px"`) — ошибка проверки.

Пример перевода из пикселей исходного проекта (полоса высотой 60 px, 1u = 0,6 px):

```toml
# было
minimum = 60     width = 120     maximum = 800      font_size = 11    padding = 4
# стало
minimum = 100    width = 200     maximum = "40%w"   font_size = 18    padding = 7
```

### Перевод в пиксели

Только в рендере (`touchbar-sets` и `touchbar-layout`): `%w` и `%h` — `N / 100 × размер стороны`, `u` — `N × размер u` после разрешения цепочки `[units]`.
- Позиции и размеры прямоугольников округляются до целых физических пикселей, чтобы края оставались чёткими.
- Ненулевой размер меньше 1 px становится 1 px.
- Размер шрифта не округляется.

Карта попаданий (`Layout`) передаётся ядру уже в пикселях поверхности.

## Пороги жестов

Палец везде одного размера, поэтому пороги жестов физические, в миллиметрах. Ядро переводит их в пиксели через `px_per_mm` поверхности.

| Порог | По умолчанию | Было в исходном проекте |
|---|---|---|
| tap: допустимый сдвиг | 1.3 мм | 8 px |
| pan: начало движения | 1.0 мм | 6 px |
| swipe: минимальная длина | 4.0 мм | 24 px |
| swipe: минимальная скорость | 40 мм/с | 240 px/с |
| запасной поиск виджета: ближайший в колонке касания, не дальше по вертикали | 3.0 мм | без ограничения |

Значения пересчитаны из пикселей исходного проекта в предположении около 6 px/мм у Touch Bar и уточняются на железе. Длительности (`hold_ms`, tap до 350 мс) остаются в миллисекундах.
