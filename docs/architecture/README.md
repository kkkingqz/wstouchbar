# Архитектура wstouchbar

Статус: черновик, согласован 2026-10-11. Детали уточняются по ходу работ.
История решений: [decisions.md](decisions.md).

## Цель

Touch Bar для MacBook с чипом T2 под Linux. Основная машина: MacBookPro16,1, Ubuntu 26.04, GNOME.

Проект переписывает [kkkingqz/touchbar](https://github.com/kkkingqz/touchbar) (ветка `t2-appletbdrm`, форк [cameroncooper/touchbar](https://github.com/cameroncooper/touchbar)). Удачные реализации переносятся оттуда, а границы процессов, модель плагинов и жизненный цикл проектируются заново.

## Принципы

1. **Одна граница привилегий.** Процессов два: `touchbard` (root) владеет железом, `touchbar-session` (пользователь) делает всё остальное. Других границ процессов нет.
2. **Функциональное ядро, императивная оболочка.** Всё поведение Touch Bar описывается детерминированной функцией `Core::handle(now, input) -> outputs` без ввода-вывода. Процессы, D-Bus, GPU и wasm живут в оболочке.
3. **Плагины доверенные.** Изоляция нужна от ошибок, а не от злого умысла: паника или зависание плагина не должны ронять Touch Bar. Прав, согласий и брокера нет.
4. **Всё содержимое поставляется плагинами и описывается декларативно.** Наборы кнопок, профили, категории приложений, привязки нажатий. Логика пишется на wasm, это чистая функция «событие → обновление».
5. **Ядро ничего не знает** о графическом окружении, железе, wasm и формате файлов. Оно видит только факты, события и действия.
6. **Нативный режим — безопасное состояние.** Без сессии, при сбое и в recovery Touch Bar отдаётся драйверу ядра, и клавиши рисует прошивка T2.
7. **Тесты проверяют инварианты.** `cargo test` проходит на свежем клоне без особого окружения.
8. **Независимость от размера и устройства.** Touch Bar — один из видов **поверхности**, позже будет окно Wayland на сенсорном мониторе. Размеры в наборах и профилях задаются относительно поверхности: по умолчанию в базовой единице `u`, вычисляемой из её размера, а по выбору автора — в процентах ширины или высоты. Пороги жестов задаются в миллиметрах. Пикселей в содержимом нет. Модели Mac с разной длиной полосы и другие поверхности используют одно и то же содержимое.

## Что убрано по сравнению с исходным проектом

| Убрано | Почему |
|---|---|
| plugin-supervisor (брокер, Landlock, seccomp, cgroups, квоты, учёт активаций) | Плагины доверенные. Изоляцию от ошибок даёт wasm внутри процесса. |
| Хранилище прав, подписи пакетов, каталог, установка пакетов | Плагины лежат в каталогах, доверие определяется местом установки. |
| Wayland-compositor в сессии, нативные плагины, старые компоненты (`Component`) | Остаётся одна модель плагинов: декларативный набор и wasm-логика. Сессия рисует сама. |
| Отдельный процесс plugin-host | Wasmtime встроен в сессию. |
| Рендер в `touchbard` (системный ряд, fallback, Fn-слой) | Ряд F1–F12 — обычный набор плагина `system`. Без сессии работает нативный режим. |
| `ws-touchbar-fn` в wsconfig | Мост Fn и затемнение в нативном режиме делает `touchbard`. |

## Схема

```
┌──────────────────────────── touchbard (root, system unit) ─────────────────────────────┐
│ режимы display/native · DRM (appletbdrm) · дигитайзер · Fn и отслеживаемые клавиши     │
│ uinput (закрытый SystemKey) · подсветка и затемнение · recovery · мост Fn (native)     │
│ владелец = активная сессия seat0 (logind) · неблокирующий event loop                   │
└───────────────▲──────────────────────────────────────────────┬──────────────────────────┘
   кадры, клавиши, │  /run/touchbar/session.sock (SEQPACKET, 32 Б)  │ касания, клавиши, режим,
   подсветка       │                                                │ Revoked, освобождение буфера
┌───────────────┴──────────────────────────────────────────────▼──────────────────────────┐
│ touchbar-session (user unit, graphical-session.target)                                   │
│                                                                                          │
│   оболочка (event loop) ──Input──▶ touchbar-core (чистое) ──Output──▶ оболочка           │
│        │                                                                │                │
│        ├── logic runtime (wasmtime): экземпляры логики плагинов         │                │
│        ├── эффекты: audio · media · open · key · spawn · dbus · timer   │                │
│        ├── desktop API ── бэкенд GNOME ── расширение GNOME Shell (D-Bus) │                │
│        ├── apps: категории приложений из desktop-файлов                 │                │
│        └── рендер: набор + состояние → UI → GL → поверхность ◀──────────┘                │
│            (swapchain Touch Bar; позже — окно Wayland, без touchbard)                    │
└──────────────────────────────────────────────────────────────────────────────────────────┘
                 ▲ /run/touchbar/control.sock
           touchbarctl (status, native/display, dev, explain, replay, setup, doctor)
```

## Глоссарий

- **Набор (set).** Декларативное описание элемента Touch Bar (раскладка, варианты по ширине, панели) в TOML. Может быть связан с модулем логики.
- **Экземпляр.** Набор, размещённый в слоте профиля, вместе со своим экземпляром логики и состоянием.
- **Профиль.** Основная раскладка полосы: слоты, группы, промежутки. Выбирается по контексту (приложение, категория).
- **Слой.** Раскладка поверх профиля, включаемая привязкой, например `system/fkeys` по Fn.
- **Панель (presentation).** Временная раскладка, которую открывает экземпляр: развёрнутый ползунок, панель громкости.
- **Факт.** Типизированное значение контекста с пространством имён: `app.id`, `app.categories`, `media.active`, `session.locked`.
- **Действие (effect).** Запрос логики к оболочке, например выставить громкость или нажать шорткат. Описывается данными, выполняет его оболочка.
- **Подписка.** Долгоживущий источник данных для логики, например изменения громкости или сигнал D-Bus.
- **Привязка.** Правило «триггер нажатия → действие», например «Fn удерживается → слой F-клавиш».
- **Поверхность.** То, на чём рисуется Touch Bar и откуда приходят касания: сама полоса (`touchbar`), позже окно Wayland (`window`), в тестах `headless`.
- **Режим.** `display` (рисует сессия через `appletbdrm`) или `native` (рисует прошивка, драйвер `hid-appletb-kbd`).
