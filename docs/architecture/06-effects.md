# Действия и подписки

Логика просит оболочку что-то сделать **действием** (разовый запрос с результатом) или **подпиской** (долгоживущий источник данных). Набор возможностей — типизированные модули плюс универсальные `spawn` и `dbus` для пользовательских плагинов. Все модули работают в любом рабочем столе, кроме `desktop`, который идёт через API рабочего стола ([07-desktop.md](07-desktop.md)).

## Общие политики

| Поле запроса | Значения | По умолчанию |
|---|---|---|
| `lifetime` | `until-hidden`: отменяется при скрытии экземпляра. `committed`: не отменяется из-за изменений интерфейса (скрытие, уничтожение, смена профиля), но логика может явно отменить его через `cancel` или заменить через `coalesce` (I6) | из таблицы ниже |
| `coalesce` | ключ объединения. Пока запрос с этим ключом выполняется, новый запрос заменяет ожидающий в очереди, и в итоге выполняется последний. Выполняющийся запрос не прерывается. Число выполненных запросов зависит от длительности выполнения: за время T при длительности d выполняется не больше ⌈T/d⌉ + 1 запросов | нет |
| `timeout-ms` | предел выполнения | из таблицы ниже |

Новый запрос `until-hidden` принимается только от Visible-экземпляра. От Hidden он отклоняется с предупреждением, без постановки в очередь и без `EffectDone`; это исключает цикл повторной выдачи после `cancelled`. Для действий из фоновой подписки скрытая логика явно выбирает `committed` (D62). Уже принятые при Visible запросы отменяются при скрытии с обычным результатом `cancelled`.

**Подписки.** Работают, только пока экземпляр `Visible`, если не задан `background = true`. После обрыва перезапускаются с backoff 1, 2, 4… 60 с, логика получает `subscription-lost`. Логика не перезапускает подписки сама: она только объявляет нужное множество. Одинаковые подписки разных экземпляров (например, одного набора на двух поверхностях) исполнитель объединяет в один источник.

**Ошибки** общие для всех видов: `unsupported` (модуль или бэкенд этого не умеет), `unavailable` (ресурс сейчас недоступен), `failed(message)`, `timeout`, `cancelled`.

**Лимиты:** ядро допускает до 8 выполняющихся запросов на экземпляр, до 4 процессов `spawn` на экземпляр и до 64 на сессию. `spawn.run` и активные `spawn.lines` используют общую квоту процессов; подписки не занимают слоты разовых действий. Пока нет слота, запрос или подписка ждёт. Сначала ядро запускает доступные ожидающие запросы, затем подписки; запросы идут в порядке принятия, а заблокированный spawn не задерживает другие виды. Исполнитель соблюдает те же ограничения при запуске и завершении реальных процессов.

`timeout` начинается при переходе запроса в `Running`, а не при постановке в очередь. `coalesce` действует в пределах поколения экземпляра и оставляет не больше одного выполняющегося и одного ожидающего запроса с ключом. Замена ожидающего даёт ему результат `cancelled`. Явный `cancel` отменяет все незавершённые запросы этого поколения с указанным тегом, включая committed; уже завершённые запросы не затрагиваются. Ожидающий запрос не посылается исполнителю, поэтому его отмена не требует `CancelEffect`.

Очередь committed сохраняется отдельно от экземпляра и после его уничтожения использует прежний `RequestId`; слоты и таймауты продолжают работать. Результаты возвращаются только живому совпадающему поколению; запоздалые и повторные завершения игнорируются.

`subscriptions = None` сохраняет желаемое множество, пустой список удаляет его. Тег идентифицирует подписку экземпляра; изменение вида создаёт новый источник и ID, изменение `background` сохраняет активный источник. Некорректное множество (в том числе повторные теги) отвергается целиком, прежнее сохраняется. Перезапуск получает новый `SubscriptionId`; данные старого ID игнорируются. Backoff сбрасывается после корректных данных. При скрытии обычной подписки её таймер снимается, но срок backoff сохраняется: повторный показ ждёт его, если он ещё не истёк. Сбой или уничтожение экземпляра прекращает также background-подписки.

## Каталог v1

### audio (`touchbar-audio`, PipeWire)

Нативный API PipeWire, без вызова `wpctl` и без `pactl subscribe`. Цели: `default-sink` и `default-source`. Подписка следует за сменой устройства по умолчанию.

| Вид | Параметры | Результат или данные | lifetime / timeout |
|---|---|---|---|
| действие `audio.set-volume` | цель, уровень 0.0–1.5 | — | `committed` / 1 с |
| действие `audio.set-mute` | цель, `on`/`off`/`toggle` | новое значение | `committed` / 1 с |
| подписка `audio.watch` | цель | `{available, volume, muted, name}` при подписке и каждом изменении | — |

### media (`touchbar-media`, MPRIS)

Перенос `touchbar-mpris`. Выбор плеера по правилу macOS: сессию держит плеер, который последним начал воспроизведение, даже на паузе.

| Вид | Параметры | Результат или данные | lifetime / timeout |
|---|---|---|---|
| подписка `media.watch` | — | `{player, status, title, artist, album, art-uri, position-ms, length-ms, can-*}` при изменении и раз в секунду во время воспроизведения | — |
| действие `media.play-pause`, `media.next`, `media.previous` | — | — | `committed` / 2 с |
| действие `media.seek` | позиция в мс | — | `committed` / 2 с |

Модуль также публикует факты `media.active`, `media.player` и `media.playback-status` для правил профилей.

### desktop (через API рабочего стола)

| Вид | Параметры | Результат или данные | lifetime / timeout |
|---|---|---|---|
| действие `desktop.shortcut` | клавиши (модификаторы + клавиша), необязательно `app` (выполнить, только если это приложение в фокусе) | — | `committed` / 1 с |
| действие `desktop.brightness.set` | уровень 0.0–1.0 | — | `committed` / 1 с |
| действие `desktop.workspace.activate` | id | — | `committed` / 1 с |
| действие `desktop.app.launch` | id desktop-файла | — | `committed` / 5 с |
| подписка `desktop.fact` | имя факта | значение или `absent` при каждом изменении | — |

Если бэкенд не умеет действие, результат `unsupported`.

### key

| Вид | Параметры | lifetime |
|---|---|---|
| действие `key.tap` | `SystemKey` | `committed` |
| действие `key.down`, `key.up` | `SystemKey` | `committed` |

`key.down` проверяет живое `Visible`-поколение владельца при выполнении (D53). Если committed-запрос дождался слота уже после скрытия или уничтожения владельца, он завершается `unavailable` без нажатия; запрос не отменяется. `key.tap` может выполняться после уничтожения владельца, если поверхность и маршрут ввода доступны; временное владение не отпускает чужую удерживаемую клавишу. `key.up` отпускает клавишу своего владельца и безопасен при повторе.

Ядро отслеживает нажатые через `key.down` клавиши и отпускает их при скрытии, сбое и уничтожении экземпляра (I9). Клавиша вводится через uinput поверхности (`touchbard`), а у поверхности без ввода клавиш — через команду `key` бэкенда рабочего стола ([16-surfaces.md](16-surfaces.md)). Если не умеют ни поверхность, ни бэкенд — `unsupported`.

### open (`touchbar-open`)

| Вид | Параметры | lifetime / timeout |
|---|---|---|
| действие `open.uri` | URI | `committed` / 5 с |

Через портал `org.freedesktop.portal.OpenURI`, а без него через `gio open`.

### timer

| Вид | Параметры | Результат | lifetime |
|---|---|---|---|
| действие `timer.after` | мс | `effect-done` по срабатыванию | `until-hidden` |
| подписка `timer.interval` | мс (минимум 16) | `subscription-data` на каждый тик | — |

### spawn (универсальный)

| Вид | Параметры | Результат или данные | lifetime / timeout |
|---|---|---|---|
| действие `spawn.run` | `argv` (без shell), `env` (добавить к окружению сессии), `stdin` (необязательно), `max-output` (по умолчанию 64 КиБ) | `{status, stdout, stderr, truncated}` | `until-hidden` / 5 с |
| подписка `spawn.lines` | как `spawn.run`, без таймаута | каждая строка stdout. При завершении процесса — `subscription-lost` и перезапуск по общим правилам | — |

Процесс запускается в своей группе процессов. Группа получает SIGTERM, а через 1 с — SIGKILL, когда запрос отменяется по общим правилам:
- `spawn.run` с `until-hidden` — при скрытии и уничтожении экземпляра;
- `spawn.run` с любым `lifetime` — при явном `cancel` от логики и по таймауту;
- `spawn.lines` — при отписке, в том числе при скрытии (без `background`) и уничтожении экземпляра.

`spawn.run` с `committed` уничтожение экземпляра не прерывает (D37, I6): процесс работает до завершения или таймаута, результат отбрасывается. `PR_SET_PDEATHSIG` гарантирует, что дочерние процессы не переживут сессию (урок исходного проекта).

### dbus (универсальный)

| Вид | Параметры | Результат или данные | lifetime / timeout |
|---|---|---|---|
| действие `dbus.call` | шина (`session`/`system`), получатель, путь, интерфейс, метод, сигнатура, аргументы в JSON | ответ: сигнатура и JSON | `until-hidden` / 5 с |
| подписка `dbus.signal` | шина, правило match (отправитель, путь, интерфейс, член) | сигнатура и JSON на каждый сигнал | — |
| подписка `dbus.property` | шина, получатель, путь, интерфейс, свойство | значение при подписке и при каждом изменении | — |

Кодирование значений: D-Bus сигнатура + JSON (массивы → массивы, словари → объекты, варианты → `{"sig": …, "value": …}`), без рекурсивных типов в WIT.

## Позже

`http.request`, `file.read` и `file.write` (в каталоге состояния плагина), `clipboard.read` и `clipboard.write`, `notify.send`. Добавляются как новые варианты `effect`: старые модули логики эти варианты просто не используют. Новые виды результатов требуют новой версии world.

### Бюджет ответов в ядре

Ядро проверяет размер будущего Handle целиком, включая заголовок, тег и данные. Результат эффекта сверх max_update_bytes заменяется Failed("too large") с предупреждением. Переполненная подписка закрывается через Unsubscribe, логика получает SubscriptionLost с Failed("too large"), затем действует обычный backoff. Экземпляр логики продолжает работать. Ошибка backend в SubscriptionLost тоже проверяется и при переполнении заменяется короткой ошибкой.

spawn.max_output допускается только когда будущий ответ с двумя потоками этого размера помещается в бюджет. Для spawn.lines применяется тот же консервативный предел; проверка происходит при приёме запроса или желаемых подписок. Последняя проверка runtime отклоняет слишком большой вход через LogicError и запись уровня Error с причиной host input budget, сохраняя Store; это ошибка входа хоста. Бюджет ответа гостя по-прежнему вызывает LogicFault.
