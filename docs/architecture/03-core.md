# Ядро: touchbar-core

Ядро содержит всё поведение Touch Bar, которое нужно проверять: маршрутизацию касаний, захваты, жесты виджетов, панели, слои, видимость экземпляров, выбор профиля, политику действий и подписок.

В ядре нет ввода-вывода, wasm, GL, системного времени и случайности. Это детерминированный автомат:

```rust
impl Core {
    pub fn new(config: CoreConfig) -> Self;
    pub fn handle(&mut self, now: Timestamp, input: Input) -> Vec<Output>;
    pub fn snapshot(&self) -> CoreSnapshot; // для status, explain и тестов
}
```

`now` приходит параметром: `Timestamp` — монотонное время в миллисекундах от старта сессии, сериализуемое, в отличие от `Instant`. Ядро не читает часы само, поэтому одна и та же последовательность входов всегда даёт одинаковые выходы. Во всех коллекциях, где важен порядок, используются `BTreeMap` или `IndexMap`, `HashMap` — нигде.

## Вход

| `Input` | Откуда |
|---|---|
| `SurfaceAdded(SurfaceInfo)`, `SurfaceChanged`, `SurfaceRemoved` | `touchbard` или другая поверхность ([16-surfaces.md](16-surfaces.md)) |
| `Touch{surface, contact, phase, x, y}` | поверхность |
| `Key{source, code, phase}` | поверхность (отслеживаемые клавиши `touchbard`) или бэкенд рабочего стола |
| `Mode{surface, display\|native}`, `Revoked{surface}` | `touchbard` |
| `Layout{surface, generation, hit_map, representations}` | рендер: карта попаданий (прямоугольники виджетов в пикселях) и выбранные варианты `responsive` в ответ на `Render` |
| `Fact{name, value \| absent}` | бэкенд рабочего стола, `touchbar-apps`, модули media и audio |
| `DesktopCapabilities{key}` | оболочка: доступность ввода клавиш из `BackendReady` рабочего стола; при потере возможности ядро отпускает удерживаемые клавиши этого маршрута |
| `Catalog(PluginCatalog)` | загрузчик плагинов: наборы, профили, категории, привязки, уже проверенные |
| `LogicDescribed{instance, description}` | runtime, после загрузки модуля |
| `LogicUpdate{instance, call, update}` | runtime: ответ логики на вызов |
| `LogicFault{instance, call, reason}` | runtime: trap, превышение времени, нарушение бюджета |
| `EffectDone{request, result}` | исполнитель действий |
| `SubscriptionData{subscription, data}`, `SubscriptionLost{subscription, error}` | исполнитель подписок |
| `Timer{id}` | оболочка, по `Output::SetTimer` |
| `FrameDone{surface, generation}` | рендер: кадр отправлен, можно планировать следующий; устаревший ответ не открывает слот кадра |

## Выход

| `Output` | Кому |
|---|---|
| `CallLogic{instance, call, invocation}` | runtime: `LogicCall::Init { config, persisted }` или `LogicCall::Handle(LogicEvent)`, с общим `CallId` |
| `CreateInstance{instance, surface, plugin, set}`, `DisposeInstance{instance}` | runtime. Создание загружает экземпляр и возвращает `LogicDescribed`, но не запускает `init`. У каждой поверхности свои экземпляры |
| `StartEffect{request, effect, policy}`, `CancelEffect{request}` | исполнитель |
| `Subscribe{subscription, kind}`, `Unsubscribe{subscription}` | исполнитель |
| `SendKey{surface, key, phase}`, `WatchKeys{surface, set}`, `Backlight{surface, limit}` | поверхность, если это есть в её `caps` |
| `DesktopKey{surface, key, phase}` | исполнитель ввода рабочего стола: маршрут клавиш при отсутствии `inject_keys` поверхности и наличии `key` у бэкенда. Если оба маршрута недоступны, запрос получает `unsupported` |
| `Render{surface, generation, scene}` | рендер: дерево сцены и изменённые экземпляры |
| `Persist{instance, fields}` | хранилище состояния |
| `SetTimer{id, at}`, `ClearTimer{id}` | оболочка |
| `Log{level, event}` | журнал и бортовой журнал |

## Модель данных

- **Каталог:** проверенные плагины, наборы, профили, категории, привязки. Заменяется целиком при перезагрузке.
- **Факты:** `BTreeMap<FactName, FactValue>`.
- **Поверхности:** описание каждой поверхности и её сцена. У каждой поверхности свои профиль, стек слоёв, панель и размещённые в них экземпляры, а также последняя карта попаданий. Выбор профиля для поверхности видит общие факты и факты `surface.*` этой поверхности. В v1 реально подключается только Touch Bar, но ядро с самого начала поддерживает несколько поверхностей одновременно ([16-surfaces.md](16-surfaces.md)).
- **Экземпляры:** состояние логики (последний `state`), видимость, запросы и подписки в работе.
- **Касания:** таблица захватов `(SurfaceId, ContactId) → Capture`.
- **Привязки:** автомат на каждую привязку сессии (см. [09-bindings.md](09-bindings.md)).

Поколения рендера уникальны в пределах ядра, в том числе после повторного подключения того же `SurfaceId`. На поверхности одновременно ожидается не больше одного кадра; изменения до `FrameDone` объединяются в следующий кадр. Поверхность с `caps.modes` начинает в `native` и ждёт подтверждения `display`; поверхность без переключения режимов всегда в `display`.

## Автоматы

### Экземпляр

```
            CreateInstance
 ┌────────┐ ─────────────▶ ┌─────────┐  LogicDescribed + init   ┌────────┐
 │ (нет)  │                │ Loading │ ───────────────────────▶ │ Hidden │ ◀─┐
 └────────┘                └─────────┘                          └────────┘   │
                                ▲                         показ  │   ▲ скрытие│
                     backoff    │                                ▼   │       │
                           ┌─────────┐   trap / таймаут    ┌─────────┐       │
                           │ Faulted │ ◀────────────────── │ Visible │ ──────┘
                           └─────────┘    (из любого)      └─────────┘
                                │ профиль больше не содержит экземпляр
                                ▼
                           ┌──────────┐
                           │ Disposed │  (терминальное, из любого состояния)
                           └──────────┘
```

| Переход | Что делает ядро |
|---|---|
| → `Hidden` (после `init`) | Применяет `state` из `init`. Подписки **без** `background` не запускаются |
| `Hidden` → `Visible` | `CallLogic(shown)`, запуск подписок экземпляра, рендер |
| `Visible` → `Hidden` | Отмена касаний экземпляра (`Cancel{Hidden}`), отмена действий с `until-hidden`, остановка подписок без `background`, затем `CallLogic(hidden)` |
| → `Faulted` | Отмена касаний (`Cancel{Fault}`), всех подписок и действий `until-hidden`. Элемент показывает заглушку. Повтор через 1, 2, 4… 60 с |
| → `Disposed` | Как `Hidden`, плюс `DisposeInstance`. Действия `committed`, и выполняющиеся, и ожидающие очереди, всё равно доводятся до конца, но их результат отбрасывается |

Экземпляр под слоем (например, когда по Fn показаны F-клавиши) остаётся `Visible`: он не получает касаний и не рисуется, но подписки работают. Логика об этом не узнаёт, а при снятии слоя картинка появляется мгновенно.

После `LogicDescribed` ядро проверяет описание и выдаёт `CallLogic(Init { config, persisted })`. Ответ приходит как обычный `LogicUpdate { instance, call, update }`: только успешный ответ на текущий `Init` переводит экземпляр из `Loading` в `Hidden`, после чего возможен показ. `Init` занимает тот же единственный слот вызова, что и `Handle`; обычные события в `Loading` не отправляются. `LogicCall` — тип хоста, а не дополнительный вариант события WIT (D41).

### Касание

```
Down ──hit-test──▶ Captured(target, widget) ──Move*──▶ ... ──▶ Up
                                                         └──▶ Cancel(reason)
```

- **Цель.** Для `Down` цель определяется по последней карте попаданий поверхности (`Layout`): панель, затем слой, затем профиль. Если касание не попало ни в один виджет, срабатывает запасной вариант из исходного проекта: ближайший виджет в той же колонке, не дальше порога по вертикали. Пороги жестов заданы в миллиметрах и переводятся в пиксели через `px_per_mm` поверхности ([16-surfaces.md](16-surfaces.md)).
- **Устаревшая карта.** Пока рендер не ответил на новый `Render`, используется предыдущая карта. Если касание попало в экземпляр, которого в новой сцене нет, оно отменяется с причиной `Layout`.
- **Причины отмены:** `Hidden`, `Layer`, `Presentation`, `Profile`, `Layout`, `Mode`, `Revoked`, `Fault`, `Hardware` (cancel от поверхности), `SurfaceRemoved`.
- **Завершение.** `Up` и `Cancel` доставляются по таблице захватов, а не по текущей сцене.

### Виджет

Жесты разбирает ядро, а логика получает только их смысл.

| Виджет | Автомат | События для логики |
|---|---|---|
| `button` | `Idle → Pressed → (Held)` | `pressed`, `long-pressed` (после `hold-ms`), `activated` (Up внутри, если не было long-press или он не задан), `released`, `cancelled` |
| `slider` | `Idle → Dragging` | `pressed`, `value-changed` (не чаще одного раза за кадр), `activated` (Up), `cancelled` |
| `scrubber` | `Idle → Scrolling → Selecting` | `value-changed`, `selected` |
| `key` | `Idle → Down` | Логика не участвует: `Down` даёт `SendKey(pressed)`, а `Up` и `Cancel` дают `SendKey(released)` |

У каждого события логики есть поле `origin`: `physical` (вызвано пальцем) или `synthetic` (отмена, вызванная ядром).

### Панель (presentation)

| Состояние | Событие | Переход |
|---|---|---|
| `Closed` | логика вернула `presentation.open` в ответ на **`physical`** событие | `Open(owner, panel, anchor)` |
| `Closed` | `presentation.open` в ответ на `synthetic` | игнорируется, `Log{warn}` |
| `Open` | `Down` вне панели и политика `outside-press` | `Closed`, `Cancel{Presentation}` для касаний внутри панели |
| `Open` | `activated` в панели и `dismiss-on-selection` | `Closed` после доставки события |
| `Open` | `transient`, касание-якорь завершено | `Closed` |
| `Open` | смена профиля или слоя, Fn, режим `native`, владелец скрыт или упал | `Closed` |

На каждой поверхности в каждый момент открыта не больше одной панели, поверхности независимы (I12). Пока панель открыта, новые `Down` идут в неё, а касания, начатые до её открытия, остаются у своих целей до завершения. Б2 из исходного проекта так невозможен по построению. Экземпляры внутри панели проходят через `Hidden` и `Visible`, как и в профиле.

### Слои

Стек слоёв над профилем управляется привязками: `layer` (пока выполняется условие, например «Fn удерживается») и `toggle-layer`. При появлении слоя касания, начатые в профиле, отменяются с причиной `Layer`, а открытая панель закрывается.

### Профиль

| Состояние | Событие | Переход |
|---|---|---|
| `Active(p)` | факты или каталог дали другой профиль `q` | если активных захватов нет — сразу `Active(q)`, иначе `Pending(p, q, deadline = now + 1500 мс)` |
| `Pending(p, q)` | последний захват завершился | `Active(q)` |
| `Pending(p, q)` | наступил `deadline` | `Cancel{Profile}` для всех захватов, `Active(q)` |
| `Pending(p, q)` | факты снова дали `p` | `Active(p)` |
| `Pending(p, q)` | факты дали `r` | `Pending(p, r)` с прежним `deadline` |

При смене профиля экземпляры, которые есть в обоих профилях (тот же плагин, набор и `logic_config` в слоте с тем же id), сохраняются. Остальные проходят через `Hidden` и `Disposed`, а новые — через `Loading`. Алгоритм выбора профиля — в [08-profiles.md](08-profiles.md).

### Действия и подписки

| Состояние | Событие | Переход |
|---|---|---|
| — | логика вернула запрос | `Requested`. Если у ключа `coalesce` уже есть запрос в работе, новый заменяет ожидающий, но не выполняющийся |
| `Requested` | у экземпляра есть свободный слот (по умолчанию 8 одновременно) | `Running`, `StartEffect` |
| `Running` | `EffectDone` | экземпляр жив — `CallLogic(effect-done)`, иначе результат отбрасывается |
| `Running` | экземпляр скрыт и `lifetime = until-hidden` | `CancelEffect`, логика получит `effect-done(cancelled)`, если экземпляр не уничтожен |
| `Requested` или `Running` | логика вернула `cancel` с тегом запроса | `CancelEffect` (для `Running` — с прерыванием, насколько его поддерживает исполнитель), `effect-done(cancelled)`. Относится к любому `lifetime` |
| `Running` | истёк `timeout` | `CancelEffect`, `effect-done(timeout)` |

Подписки — это желаемое множество, которое возвращает логика. Ядро вычисляет разницу с текущим множеством и выдаёт `Subscribe` и `Unsubscribe`. Перезапуск после `SubscriptionLost` идёт с backoff 1, 2, 4… 60 с, логика получает `subscription-lost`.

## Инварианты

Их проверяют property-тесты на случайных последовательностях входов (см. [13-testing.md](13-testing.md)).

1. **I1.** У каждого `Down` ровно одно завершение (`Up` или `Cancel`), и оно доставлено той же цели, что и `Down`.
2. **I2.** После завершения касания его нет в таблице захватов. Если все касания завершены, таблица пуста.
3. **I3.** `Pending` профиля всегда разрешается не позже `deadline`.
4. **I4.** На каждой поверхности открыта не больше одной панели. Панель закрывается, если её владелец перестал быть `Visible`.
5. **I5.** Скрытый экземпляр не получает действий и событий касаний и не держит подписок без `background`.
6. **I6.** Принятое ядром действие `committed` не отменяется из-за изменений интерфейса: скрытия, уничтожения экземпляра, смены профиля, слоя или панели (сценарий A2 исходного проекта). Его отменяют только таймаут, явный `cancel` от логики и замена через `coalesce`: ожидающий запрос заменяется новым с тем же ключом, а выполняющийся не прерывается.
7. **I7.** Результат действия или данные подписки никогда не доставляются экземпляру, который уничтожен или пересоздан.
8. **I8.** Логика не получает событий в `Loading`, `Faulted` и `Disposed`.
9. **I9.** Каждая отправленная клавиша `pressed` получает `released`, даже при отмене касания, скрытии, смене режима или отзыве. Ядро выдаёт завершающие релизы; `touchbard` независимо отпускает введённые клавиши перед native, отзывом и закрытием соединения (D43).
10. **I10.** Сбой одного экземпляра не меняет состояние других, если не считать перераскладки.
11. **I11.** Для поверхности в режиме `native` ядро не выдаёт `Render` и новые `SendKey(pressed)`. Исключение — завершающие `SendKey(released)` при переходе в native или отзыве (D43). Ядро не выдаёт команд, которых нет в `caps` поверхности.
12. **I12.** Поверхности независимы: события одной поверхности не меняют касаний, панелей и слоёв другой, если не считать общих фактов.

## Бортовой журнал

Ядро — чистая функция. Поэтому любую ситуацию воспроизводят **полное состояние ядра на начало отрезка и входы после него**. Одних входов, начальных фактов и хешей каталога для этого мало: ядро к началу буфера уже имеет захваты, экземпляры, очереди, таймеры и состояние логики.

```rust
impl Core {
    pub fn checkpoint(&self) -> CoreState;          // полное сериализуемое состояние
    pub fn restore(state: CoreState) -> Result<Self, RestoreError>;
}
```

- `CoreState` содержит **версию формата**, **`CoreConfig`** (таймауты, пороги, лимиты: с другими значениями те же входы дали бы другие выходы) и всё состояние: каталог целиком (а не хеши), факты, поверхности и сцены, экземпляры с последним `state` логики, очереди вызовов, запросы и подписки, захваты, автоматы привязок и таймеры, счётчики идентификаторов. `CoreSnapshot` для `status` — его урезанное представление.
- `restore` берёт конфигурацию из самого `CoreState`. Неизвестная версия формата даёт `RestoreError::Version`: дамп чужой версии не воспроизводится молча с другими правилами.
- Инвариант детерминизма: `restore(checkpoint(c))` после тех же входов даёт те же выходы, что и `c`. Его проверяет property-тест.
- Оболочка делает **начальную** контрольную точку сразу после `Core::new`, затем каждые 2000 входов, и хранит две последние вместе со всеми входами после старшей из них. Дамп содержит старшую из хранимых контрольных точек и все входы после неё: до 4000, а пока входов меньше 2000 — начальную точку и все входы с начала сессии ([12-diagnostics.md](12-diagnostics.md)).
