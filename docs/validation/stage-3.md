# Приёмка этапа 3

Дата: 2026-10-15. План: [stage-3-session.md](../plans/stage-3-session.md), S1–S16.

## Код и окружение

S1–S15 — ветка `stage-3-session`, коммит `9839b0b`. Проверка S16 добавляет
информационный пример замеров, актуализирует документы и исправляет очистку
временного каталога в тесте кеша; код библиотек после S15 не меняется.

Свежий клон создан командой
`git clone --no-local --branch stage-3-session /source /src` в отдельном чистом
контейнере `docker.io/library/ubuntu:26.04`, Ubuntu 26.04.1 LTS, x86_64.
В него не передавались target, готовые wasm или кеши Cargo/Rustup. Установлены
build-essential, pkg-config, clang, libpipewire-0.3-dev, ca-certificates, curl и git;
официальный rustup установил закреплённые Rust/Cargo 1.98.1, rustfmt, clippy и
wasm32-unknown-unknown. Обычные тесты сами собрали wasm-фикстуры.
После первого прохода в этот клон скопированы только пример S16 и исправление
тестового каталога с соответствующими Cargo.toml/Cargo.lock; проверки повторены.

Проверки окружений, длинные свойства и замеры выполнены в отдельном рабочем
контейнере Ubuntu 26.04 с тем же toolchain и lockfile. Mesa — 26.0.8-1ubuntu0.3,
PipeWire — 1.6.2, Weston — 14. Проверки D-Bus, PipeWire и Wayland создают свои
приватные службы; они не используют рабочие службы пользователя.

## Ручная проверка

На машине разработчика (Ubuntu 26.04.1, GNOME Wayland) запущен настоящий
`touchbar-session --simulator --desktop=fake` с настоящим PipeWire и двумя
поверхностями: `touchbar=2008x60@6.2ppmm` и `window:test=1200x160@4ppmm`.
Сервис проекта не устанавливался. Конфигурация, данные, кеш и состояние
демонстрации изолированы во временном каталоге.

Пользователь проверил VOL, изменение настоящей громкости и обратное обновление,
MIC, удержание около 420 мс, Fn через правый Alt, Ctrl+T и независимость панелей
двух поверхностей. Ответ: «все ок, кнопки работают. но были открыты две панели
разного размера». Разные размеры ожидаемы: два окна были запущены специально
для проверки разных поверхностей. После проверки окна закрыты.

Отдельно команда `touchbarctl sim fact display.brightness=0.4` обновила значение
обоих экземпляров. Рабочий стол здесь fake; это не проверка настоящей яркости
GNOME. Интеграция GNOME и аппаратный Touch Bar остаются этапами 5 и 4.

## Замеры

Информационный пример:

```sh
cargo run -p touchbar-session --example session_benchmark --release --locked
cargo run -p touchbar-session --example session_benchmark --release --locked -- --render-node /dev/dri/renderD128
```

Фиксированные Inter/en-US, временное дерево настоящих плагинов, поддельные
внешние эффекты, кадр 2008×60. По 100 измерений CPU и GL после прогрева.
Полное изменение чередует тему; частичное меняет подпись одного volume.
Счётчики подтверждают 300 и 100 построенных деревьев соответственно.
GL-замер включает полный damage и получение пикселей, не вывод на монитор.

| Замер | Mesa llvmpipe (без /dev/dri) | Intel UHD Graphics 630 |
|---|---:|---:|
| Каталог, холодный дисковый кеш | 275,696 мс | 220,307 мс |
| Каталог, тёплый кеш | 6,384 мс | 4,898 мс |
| CPU, полный кадр, p50 / p99 | 1,474 / 1,774 мс | 1,208 / 1,373 мс |
| CPU, один экземпляр, p50 / p99 | 1,366 / 1,705 мс | 1,108 / 1,259 мс |
| GL, полный кадр, p50 / p99 | 0,862 / 1,020 мс | 0,953 / 3,588 мс |
| Подготовка fixture до первого кадра | 22,061 мс | 44,872 мс |
| RSS процесса примера | 131792 КиБ | 109784 КиБ |

GPU-прогон использовал EGL device `/dev/dri/renderD128`, переданный контейнеру;
устройство — i915, PCI 8086:3e9b, CoffeeLake-H GT2. Оба backend сообщили
OpenGL ES 3.2 Mesa 26.0.8-1ubuntu0.3. Сравнение информационное: это отдельные
запуски под меняющейся нагрузкой, а не оценка преимущества одного backend.

Нативный **debug**-симулятор на рабочем GNOME: первый Wayland frame callback
через 1072,746 мс, все экземпляры инициализированы через 9985,693 мс,
RSS 159032 КиБ. Это холодный запуск одновременно с компиляцией двух наборов
проверок, с двумя окнами и настоящим PipeWire. Значения не характеризуют
задержку прогретой release-сессии. `fixture_first_frame_ms` из примера включает
копирование временных файлов и настройку шрифтов и не подменяет этот замер.

## Итоговое ревью и исправления

2026-10-16 независимый reviewer проверил всю ветку `dbe2847..f93f26a`,
архитектуру, план, решения и приёмку. Первый запуск reviewer 15 октября
не начался из-за лимита модели; отчёт получен только при следующем запуске.
Повторного ревью исправлений нет: проверка — воспроизводящие тесты и общий прогон.

Исправления выполнены 2026-10-17 в одном проходе. Для каждого дефекта
сначала получен падающий регрессионный тест, затем проверено исправление.
В проверку входят:

- SVG: отключены файловый и data-URL resolvers usvg с явной диагностикой;
  обычный внешний файл, встроенное изображение и FIFO проверены. FIFO-тест
  изолирован в процессе с таймаутом; локальный векторный `use` работает.
- Шейдеры: структурная проверка целого кадра отделена от квоты экземпляра.
  Пять наборов, девять разных программ и панель поверх четырёх наборов
  воспроизводили отказ кадра; теперь композиции допустимы.
- Motion: по согласованному D104 сдвиг/масштабирование интерактивного
  поддерева и привязки этих параметров отвергаются при разборе набора.
  Прозрачность, стабильный таймлайн и декоративные преобразования сохраняются.
  Контракт ядра и версии checkpoint/replay не изменены.
- Watcher: недоступные/исчезнувшие каталоги и бюджет наблюдения не завершают
  сессию. Сохраняются полезные watches, ограниченная диагностика попадает
  в журнал сессии, обслуживание повторяется. Проверка прав запускается
  без root-привилегий, даже если общий прогон выполняется от root.
- Текст: CpuPainter потребляет неиспользуемые уведомления о вытеснении;
  частая смена текста и ошибка следующего примитива не оставляют растущую историю.

Оставлено мелкое замечание: изменение desktop-бэкенда в конфигурации принимается
через reload, но фактический fake/null backend остаётся выбранным при старте.
Для применения нужен перезапуск; отдельной диагностики пока нет.
