## Проверки

Для ошибок поведения сначала воспроизведён сбой регрессионным тестом,
затем проверено исправление. После каждого пункта выполнены Clippy и полный
набор тестов рабочего пространства с `PROPTEST_CASES=2000`.
Обычный итоговый прогон после уточнения I10: 337 тестов, 0 ошибок;
ручной benchmark по умолчанию пропускается.
`cargo fmt --all --check` и Clippy с `-D warnings` проходят.

Команды итоговых проверок:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
PROPTEST_CASES=2000 cargo test --workspace --locked
PROPTEST_CASES=100000 cargo test -p touchbar-testkit --release --locked
```

Оптимизированный Move сравнивается с полным путём обработки по командам
и полному сериализованному состоянию после входов. Проверены кнопка,
ползунок и scrubber; наличие и отсутствие логики; две поверхности;
очереди вызовов и эффектов; FrameDone; восстановление контрольной точки;
некорректные координаты, отсутствующие контакты и поверхности, native,
ожидание профиля и обратное время.

При Pending любой поверхности Move использует полный путь. Это необходимо:
скрытие может убрать последнюю физическую работу из очереди после проверки
готовности профиля, и следующий вход должен завершить переключение.
Дифференциальный тест воспроизвёл этот случай и проверяет сохранённое поведение.

При наступившем сроке ближайшего таймера также используется полный путь.
Дополнительное ревью обнаружило, что иначе Move пропускает возобновление
подписки, чей backoff уже закончился, до доставки входа Timer. Регрессия
сравнивает команды и состояние до, в момент и после срока, для обычной и
фоновой подписки, другой поверхности и неизвестных контакта и поверхности.

Дополнительный проход ревью не обнаружил других замечаний к пунктам 1–8.

Первый заключительный прогон release с `PROPTEST_CASES=100000` обнаружил I10;
счётчик выполненных сценариев при остановке: 63 876.
Минимальный сценарий: касание на второй поверхности → общий факт app.id →
native второй поверхности → отказ логики первой поверхности. При отказе
завершается прежний Pending второй поверхности и уничтожается старый набор.

и временем также завершает этот Pending и уничтожает тот же экземпляр.

Пользователь согласовал D65: завершение прежнего Pending считается допустимой

## Контрольный замер Move

Команда ручного benchmark:

```sh
cargo test -p touchbar-core --lib benchmark_touch_moves -- --ignored --nocapture
```

В одном процессе debug-сборки, при двух поверхностях, 40 экземплярах,
360 виджетах и 10 000 Move:

| Путь | Время |
|---|---|
| Полная синхронизация | 1,117 с |
| Оптимизированный Move | 17,22 мс |

Около 65 раз в этом контрольном сценарии. Замер использует статические наборы
и незавершённый кадр, чтобы измерить стоимость обработки Move без новых кадров.
Сцена клонируется при выдаче Render с учётом FrameDone; клонирование на каждый
Move в исходном замечании описано неточно.

Проверки выполняются в контейнере `wstouchbar-stage1-build`, Rust 1.98.1.
Сервисы проекта, аппаратные бэкенды и реальные эффекты не запускались.
